# Pair Polymath — v0.2 Implementation Plan

> **Predecessor:** [lean v1 plan](../../../.claude/specs/2026-05-11-polymath-advisor-extraction-plan.md) — shipped as commits `9739e5c..d5345c7`, 12 commits, 43/43 bats, M1–M6 complete.
>
> **Process:** Subagent-driven, one milestone per dispatch. Each milestone gets: base subagent → GPT-5.5 review (`git show <sha> | llm -t review-code -m gpt-5.5`) → fix-up commit → mark complete. Same as lean v1.

## Scope summary

Built across 4 phases, each independently shippable. Phase 1 is the bare minimum that unlocks installing on another machine. Phases 2–3 are quality-of-life. Phase 4 is public-ready polish.

| Phase | Outcome | Effort |
|---|---|---|
| **P1** Deploy-ready | `polymath doctor`, GitHub push + alpha tag, Docker-Linux CI | 3–4h |
| **P2** Operate & debug | `disable`/`enable`/`logs`/`update`, installer `--dry-run`/`--yes`/`--no-sudo` + audit log | 3–4h |
| **P3** Cost transparency | USD telemetry → `metrics.jsonl`, `polymath cost`, privacy log | 3h |
| **P4** Public-ready | docs/, CONTRIBUTING/CoC/SECURITY, asciinema, self-test, public push, plugin.json | 4–5h |
| **Total** | | **13–16h** |

**Versioning:** v0.2.0 ships when P1+P2+P3 complete. v0.3.0 is P4 (public + marketplace). `v0.1.0-alpha` (private tag) lands at end of P1.

---

## Decisions locked in

Carried forward from lean v1 + new for v0.2:
1. **No marketplace until v0.3.** v0.2 ships to private repo only.
2. **No heavy `migrate-from-bare.sh`** — replaced with detection + printed manual steps + request counter (per STRATEGIC_FOUNDER advisory). Build the full script only if request count ≥ 3 over 14 days.
3. **Audit log: append-only JSONL** at `~/.claude/pair-polymath/install.log`. Fields: `{ts, action, command, exit_code, stderr_tail}`.
4. **USD telemetry: end-of-cycle rollup**, not per-call hook. Static price table for `gpt-5-mini`/`gpt-5`/`gpt-5.5`. Multiply call count × avg-tokens × $/M. v0.3 may add real `--usage` parsing.
5. **CI matrix gains a Docker-Linux installer test** — proves the `apt-get` path is real, not just typed.
6. **Golden CLI snapshots** for `--dry-run`, `--yes`, conflict-prompt paths to lock UX (per UX_DESIGN advisory).

## Phase 1 — Deploy-ready (3–4h)

### P1.1 `polymath doctor` (~1.5h)

**File:** `bin/polymath` (add `doctor` subcommand) + new helper `lib/doctor.sh`.

Checks, in order, with per-check ✅ / ⚠ / ✗:
1. `bash --version` ≥ 3.2
2. `jq --version` present
3. `llm --version` present, ≥ 0.20
4. `llm keys list` includes `openai`
5. `$CLAUDE_DIR/settings.json` exists + parses as JSON
6. `settings.json` `statusLine.command` resolves to our `bin/statusline.sh` (or another script — warn, not fail, since the user may have kept theirs at install time)
7. `settings.json` `hooks.UserPromptSubmit` references `inject-monitor-insight.sh`
8. `settings.json` `hooks.PostToolUse` references `cache-test-result.sh`
9. `$PP_CACHE_DIR` writable
10. Today's budget file readable: `pp-budget-$(date +%Y%m%d).txt`
11. Lens registry: `pp_load_lenses` returns ≥1 lens
12. Prompts: all 6 built-in files present + valid UTF-8
13. Optional real-network check (only with `--network` flag): `echo "ok" | llm -m gpt-5-mini "respond: ok"` — verifies key + reachability for ~$0.0001

**Exit codes:** 0 = all green or yellow, 1 = any red.

**Output format:** Each line `✓ check name (detail)` or `✗ check name — reason`. Summary at end: "N green, M yellow, K red. Status: HEALTHY / DEGRADED / BROKEN".

**Tests** (`test/doctor.bats`):
- Healthy state → exit 0
- Missing jq (`PATH` stripped) → exit 1 + jq red line
- Settings.json missing → exit 1
- Settings.json malformed → exit 1
- Lens dir empty → exit 1
- All-green run with `--network` skipped → exit 0

### P1.3 Docker-Linux CI installer test (~1h)

**File:** `.github/workflows/install-test.yml`

Workflow:
- Trigger: push, PR
- Job: `installer-clean-ubuntu`
  - Container: `ubuntu:22.04` (no jq, no llm, no `~/.claude/`)
  - Steps:
    1. `apt-get update && apt-get install -y curl python3-pip git ca-certificates sudo`
    2. Checkout repo
    3. Run `./bin/install.sh --yes --no-sudo` (flags from P2.3)
    4. Assert `~/.claude/settings.json` parses + references our paths
    5. Assert `~/.claude/pair-polymath/` exists with 0700
    6. Assert audit log at `~/.claude/pair-polymath/install.log` has entries
    7. Run `bash bin/polymath doctor` — exit 0 or only yellow
    8. Run smoke test: `cat test/fixtures/stdin-sample.json | bash bin/statusline.sh` → exit 0

**Acceptance:** Phase 1 done when (a) `polymath doctor` green on author's machine, (b) clean Docker run green in CI, (c) v0.1.0-alpha tag pushed to private GitHub.

## Phase 2 — Operate & debug (3–4h)

### P2.1 `polymath disable` / `polymath enable` (~30min)

**File:** `bin/polymath` (extend case statement).

```bash
polymath disable    # echo 'PP_EXTERNAL_LLM=0' >> user.env (idempotent)
polymath enable     # remove PP_EXTERNAL_LLM=0 line OR set to 1
```

Both subcommands:
- Read `$CLAUDE_DIR/pair-polymath/config/user.env`
- Atomic edit via tmp + mv
- Print resulting state ("LLM cycle disabled / enabled. New cycles take effect within 5 min.")

**Tests** (`test/cli.bats` extension):
- `disable` adds line, `enable` removes it
- Idempotent: `disable; disable` results in one line
- Status afterwards shows correct flag

### P2.2 `polymath logs` (~45min)

**File:** `bin/polymath` (extend).

Shows last N (default 10) cycle observations:
```
2026-05-11 14:42  UX_DESIGN: …
2026-05-11 14:42  ENGINEERING: …
2026-05-11 14:42  SECURITY: …  ← DROPPED (critique: too generic)
…
```

Sources:
- Per-lens cache files (`cc-monitor-${session_id}-${lens_id}.txt`)
- Verdict sidecars (`*-verdict.txt`) for DROP annotations
- Last 7d, grouped by date

Flags:
- `--follow` / `-f`: `tail -F` on the most recent cache (refresh as cycles complete)
- `--lens NAME`: filter to one lens
- `-n N`: last N entries (default 10)

**Tests** (`test/cli.bats`):
- Empty cache → "no observations yet" + exit 0
- Populated cache → shows observations in reverse-chron order

### P2.3 Installer flags + audit log (~1.5h)

**File:** `bin/install.sh` (substantial extension) + helper `lib/audit-log.sh`.

New flags:
- `--dry-run` — print every action with `[DRY-RUN]` prefix, make zero FS changes, exit 0
- `--yes` — skip all interactive prompts (use defaults: install missing deps, keep existing statusLine, skip key prompt if not in env)
- `--no-sudo` — refuse to run `sudo`; if a dep needs it, print manual command and exit 1
- `--non-interactive` — alias for `--yes --no-sudo` (CI-friendly)

**Bare-install detection (replaces full migrate-from-bare):**
At install start, check `$CLAUDE_DIR/statusline-command.sh` exists. If yes:
```
⚠ Detected existing 'bare-install' setup at ~/.claude/statusline-command.sh.
  Pair Polymath is a plugin that supersedes this. Recommended:
    1. cp ~/.claude/settings.json ~/.claude/settings.json.pre-pp-bak
    2. (Optional) Move ~/.claude/statusline-command.sh aside.
    3. Continue this installer — it will prompt before replacing your statusLine.
  This installer will NOT auto-migrate. Want to migrate manually first? [y/N]
```

Increment `~/.claude/pair-polymath/cache/migration-requests.txt` counter for telemetry.

**Audit log** (`lib/audit-log.sh`):
```bash
audit_log() {
  # audit_log ACTION COMMAND EXIT_CODE STDERR_TAIL
  printf '{"ts":"%s","action":"%s","command":%s,"exit_code":%s,"stderr":%s}\n' \
    "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$1" \
    "$(jq -Rsn --arg s "$2" '$s')" "$3" \
    "$(jq -Rsn --arg s "$4" '$s')" \
    >> "$AUDIT_LOG"
}
```

Every dep install, key set, settings.json mutation, smoke test → one JSONL line.

**Golden CLI snapshots** (per UX_DESIGN advisory) — `test/fixtures/install-dry-run.golden.txt`, `install-yes.golden.txt`, `install-conflict.golden.txt`. Bats compares actual vs golden, ignoring timestamps.

**Tests** (`test/install.bats` — new file):
- `--dry-run` makes no FS changes (snapshot HOME before/after)
- `--yes` runs headless without TTY
- `--no-sudo` exits 1 with clear msg if apt-get path triggered
- Bare-install detection prints the warning + bumps counter
- Audit log has expected entries after install

### P2.4 `polymath update` (~30min)

**File:** `bin/polymath` (extend).

```bash
polymath update
```
- `git -C "$PP_ROOT" fetch --tags`
- If new commits or new tag: print diff summary (`git log --oneline OLD..NEW`)
- Ask confirm `[Y/n]` (unless `--yes`)
- `git pull --ff-only` (no merge commits)
- Re-run `./bin/install.sh --yes` (idempotent: hooks de-duped, no overwrite unless changed)

**Acceptance:** Phase 2 done when `polymath {disable,enable,logs,update}` all work + installer `--dry-run`/`--yes`/`--no-sudo` exit cleanly with golden-snapshot tests green.

## Phase 3 — Cost transparency (3h)

### P3.1 USD telemetry to `metrics.jsonl` (~1.5h)

**File:** `bin/statusline.sh` (instrument cycle end) + new `lib/metrics.sh`.

**Approach (lean):** Static price table, end-of-cycle rollup.

`lib/metrics.sh`:
```bash
# Price per 1M tokens (input | output), as of v0.2
# Source: docs to be updated when API prices change
PP_PRICE_GPT_5_MINI_IN_PER_M="0.25"
PP_PRICE_GPT_5_MINI_OUT_PER_M="2.00"
PP_PRICE_GPT_5_IN_PER_M="1.25"
PP_PRICE_GPT_5_OUT_PER_M="10.00"
PP_PRICE_GPT_5_5_IN_PER_M="2.50"
PP_PRICE_GPT_5_5_OUT_PER_M="15.00"

# Avg-token assumptions per call type
PP_AVG_TOK_PLANNER_IN="800";   PP_AVG_TOK_PLANNER_OUT="50"
PP_AVG_TOK_ANALYST_IN="2200";  PP_AVG_TOK_ANALYST_OUT="180"
PP_AVG_TOK_CRITIQUE_IN="3500"; PP_AVG_TOK_CRITIQUE_OUT="500"
PP_AVG_TOK_INV_IN="1500";      PP_AVG_TOK_INV_OUT="100"
PP_AVG_TOK_RETRY_IN="2500";    PP_AVG_TOK_RETRY_OUT="180"

# Track counts during cycle (incremented at each run_llm call site)
metrics_increment_call() {
  local call_type="$1"  # planner | analyst | critique | inv | retry
  local model="$2"
  echo "${call_type}:${model}" >> "$PP_METRICS_TMP"
}

# End-of-cycle: roll up counts → USD estimate → append to metrics.jsonl
metrics_flush_cycle() {
  local session_id="$1"
  # ... awk to count types + compute usd ...
  printf '{"ts":"%s","session":"%s","calls":%s,"usd_est":%s,"by_type":%s}\n' \
    ... >> "$PP_METRICS_FILE"
  rm -f "$PP_METRICS_TMP"
}
```

Cycle instrumentation:
- 5 call sites in `statusline.sh` → wrap with `metrics_increment_call "<type>" "<model>"`
- After cycle subshell exits → `metrics_flush_cycle`

**Tests** (`test/metrics.bats`):
- 9 incrementer calls (1 planner + 7 analyst + 1 critique) → flushed JSON has correct counts + USD ≈ expected
- Worst-case 23 calls → USD scales linearly

2026-05-10      12      108      $0.59
2026-05-11       8       72      $0.41

**Tests** (`test/cli.bats` extend):
- Empty metrics.jsonl → "no cost data yet" + exit 0
- Populated file → table matches expected aggregation

### P3.3 Privacy log (~30min)

**File:** `bin/statusline.sh` (instrument cycle) + write to `cache/last-cycle-payload.json`.

Before each LLM call, capture what we're about to send (without the call itself):
```json
{
  "ts": "2026-05-11T14:42:00Z",
  "session": "abc123",
  "lens": "ENGINEERING",
  "call_type": "analyst",
  "input_preview": "<first 500 chars of $lens_grounded>",
  "input_bytes": 4287,
  "model": "gpt-5-mini"
}
```

Overwrites `last-cycle-payload.json` each cycle (no archiving — privacy log, not audit). Lets users see exactly what got sent.

**Tests** (`test/privacy-log.bats` — new):
- After one cycle, file exists + parses + has all expected fields
- Sensitive var (`OPENAI_API_KEY`) not present in `input_preview` even if set in env

**Acceptance:** Phase 3 done when `polymath cost` shows real numbers from 1 week of cycles + privacy log readable.

## Plan critique (self-review before execution)

Things this plan might be wrong about:
1. **USD estimate accuracy.** Static token avg × call count may underestimate by 2-3x if real grounded-facts strings are larger than assumed. v0.3 should add real-token parsing via `llm --usage`. Flagged in risk inventory.
2. **`polymath update` doing `--ff-only` rules out user-local modifications.** If user has local edits to `bin/polymath`, `update` will fail. Documented in `--update` help text: "uncommitted local changes block the update."
3. **Golden CLI snapshots will need re-baselining.** Whenever copy changes, snapshots fail. Acceptable cost for UX stability; document the re-baseline workflow.
4. **Bare-install detection counter is anonymous local-only** — useless for cross-machine aggregation. v0.3 may add opt-in telemetry. For now: author manually polls their own counter as proxy.
5. **Docker CI bash version.** ubuntu:22.04 ships bash 5.x; macOS testing uses bash 3.2. The bash 3.2 path is covered by author's daily use + manual smoke. Worth noting in `docs/troubleshooting.md`.

## What this plan deliberately does NOT include

- **Real per-call USD tracking** via `llm --usage` parsing → v0.3
- **Cross-machine telemetry / call-home** → v0.3 + opt-in
- **Alternate LLM providers** (Anthropic, local models) → v0.3 (Simon Willison's `llm` already supports this; just needs default-model docs)
- **Marketplace approval workflow** → blocking on v0.3, not v0.2
- **Real heavy `migrate-from-bare.sh`** → conditional on ≥3 requests over 14 days
- **Self-migration of the author's own ~/.claude/** → owner action, not subagent work (user direction)
