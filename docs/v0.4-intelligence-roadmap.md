# Pair Polymath — v0.4 Intelligence Roadmap

**Constraint locked (2026-05-13):** stay bash 3.2-portable. v0.3 shipped sophisticated subsystems (memory, eval-gate, calibration harness) in bash; v0.4 holds that boundary. No Python rewrite.

**Goal:** Move polymath from **forum** (7 lenses fire on thin context, every cycle) to **navigator** (1–3 voices fire on richer context, chosen by phase). Plus close the noise wound: dismissed observations should stay dismissed.

**The two intelligence shifts** (the core of v0.4, mutually subsidizing):

1. **See more, see better** — replace the 5 KB transcript tail with filtered conversation (user messages + Claude text, drop tool outputs) plus a structured tool-call summary. ~3× input tokens, ~5× signal density. From prior brainstorming options A–E, this is option B + D.
2. **Pick the right voice** — a router meta-lens reads conversation phase / confidence / outcome and picks 1–3 lenses to fire instead of all 7. ~60% reduction in fan-out per cycle.

These cancel out on cost: router cuts call count, freeing budget for the wider context. Net per-cycle spend lands flat to −20% vs v0.3.

**Plus a memory-aware noise floor:** `polymath dismiss` + memory-fed analyst constraints, so observations like "browser-side keys are intentional" stop re-firing on every cycle forever.

**Plus a small foothold for v0.6:** category directory restructure for lenses, 5 new lenses, one preset. Validates the 35-lens taxonomy without shipping all of it.

---

**Non-goals for v0.4** (each tracked to a later version with a reason):

| Deferred | To | Why |
|---|---|---|
| Auto-review (Stop hook + classifier + reviewers) | v0.5 | Wants intelligence layer stable first; auto-review is louder, dismiss channel must exist before that lands |
| Multi-select install UX + full 35-lens taxonomy | v0.6 | Router is the cost-control prerequisite for many lenses; ship router first |
| `polymath lens add` interactive authoring | v0.6 | Lower priority than foundational intelligence work |
| Internet access for analysts (Brave / OpenAI `web_search`) | indefinite | User decision 2026-05-13: skip |
| Python rewrite | unscheduled | No measured pressure; bash 3.2 ceiling not yet hit |
| Subagent integration (`SubagentStop` hook) | v0.5+ | Bundled with auto-review |
| MCP server mode | v1.0+ | Far horizon |

## Architecture deltas (the new modules and their owners)

Following the project invariant *"each lib owns one invariant — fix bugs by editing the owner, not the caller":*

| Module | Owns |
|---|---|
| `lib/transcript.sh` (new) | Filtered transcript extraction. Reads `$transcript_path` JSONL, emits user messages + Claude assistant text only, drops tool inputs/outputs larger than `PP_TRANSCRIPT_TOOL_TRUNC=512` bytes |
| `lib/tool-summary.sh` (new) | Structured summary of recent tool calls (Read / Edit / Write / Bash) as a one-line-per-call block. Bounded to `PP_TOOL_SUMMARY_MAX=20` entries |
| `lib/router.sh` (new) | Meta-lens that maps conversation signals → list of lens IDs to fire this cycle. One LLM call (gpt-5-mini, cheapest) returns `{primary: [...], surprise: optional<lens_id>}` |
| `lib/dismiss.sh` (new) | Suppression rule storage (`~/.claude/pair-polymath/dismiss/<project_hash>.jsonl`), CLI commands (`add`, `list`, `undo`), and `pp_dismiss_render` for injection into analyst prompts |
| `bin/statusline.sh` (modify) | Fan-out path becomes router-gated. Old `for lens in $enabled_lenses` becomes `for lens in $($router_output)`. Tool summary + filtered transcript replace raw transcript tail |
| `prompts/analyst-primary.md` (modify) | New placeholders: `${transcript_filtered}`, `${tool_summary}`, `${project_constraints}` |
| `lenses/*.json` system prompts (modify) | Append constraint stanza: *"Constraints from prior sessions in this project: ${project_constraints}. Do not flag these unless the diff materially changes the constraint."* |
| `lib/lens-loader.sh` (modify) | Walk `lenses/{category}/*.json` directory tree instead of flat `lenses/*.json` |
| `hooks/session-end.sh` (new) | SessionEnd hook: roll up cycle observations into one memory entry for the session |

## Phase 1 — Filtered transcript + tool-call summary

**Why first:** every subsequent phase improves with better input. Router signal detection runs against the conversation, not the file. Dismiss rules only suppress what the model would have said — that's only useful when the model is seeing the right thing in the first place.

**Budget:** 4 work-days, 1 PR.

**Files:**
- Create `lib/transcript.sh`. Functions:
  - `pp_transcript_filter(transcript_path) → filtered text` — reads JSONL, keeps `{role:"user"}` text + `{role:"assistant"}` text content, drops `tool_use` / `tool_result` blocks larger than `PP_TRANSCRIPT_TOOL_TRUNC` bytes (default 512). Caps output at `PP_TRANSCRIPT_MAX=16384` bytes from the tail.
  - `pp_transcript_tool_calls(transcript_path) → JSON array` — extract last `PP_TOOL_SUMMARY_MAX` tool invocations with `{tool, target, summary}`.
- Create `lib/tool-summary.sh`. Function:
  - `pp_tool_summary_render(tool_calls_json) → text` — formats as `Read   src/api.ts (12 KB)` / `Edit   src/api.ts (+45 −12)` / `Bash   pnpm test (exit 1)`.
- Modify `bin/statusline.sh`:
  - Replace `transcript_tail=$(tail -c 5120 "$transcript_path")` with calls to the two functions above.
  - Pass `${transcript_filtered}` and `${tool_summary}` into the analyst subshell scope.
- Modify `prompts/analyst-primary.md` — replace `${transcript_tail}` with the two new placeholders.
- Modify `lib/prompt-loader.sh` — extend `PP_PROMPT_VAR_ALLOWLIST` with the two new names.
- Modify `lib/grounding.sh` — `pp_redact_secrets` runs over filtered transcript output before injection (existing redaction patterns already handle the canonical secret shapes).
- Modify `test/eval/eval.bats` — re-run baseline with filtered transcript, assert useful% rises ≥5pp on at least 4 of 7 lenses. If it doesn't, the filter is wrong (probably too aggressive).
- Create `test/transcript.bats` — fixture-driven tests for `pp_transcript_filter` covering tool-output truncation, byte cap, role filtering, empty transcript.

**Gate:** Eval delta shows useful% ≥+5pp on majority of lenses; hallucination% does not rise (would indicate the model is grasping at the wider context).

**Risk:** Tool output truncation drops a critical signal (e.g., a stack trace that would have explained the user's frustration). Mitigation: `PP_TRANSCRIPT_TOOL_TRUNC` is tunable per user; eval-gate detects regressions before merge.

## Phase 2 — Router meta-lens

**Why second:** with the filtered transcript in place, the router has signal to work with. Phase / confidence / outcome detection on raw tool dumps would be noise.

**Budget:** 4 work-days, 1 PR.

**Files:**
- Create `lib/router.sh`. Functions:
  - `pp_router_detect_signals(filtered_transcript, tool_summary, cache_test_result) → JSON` — emits `{phase, confidence, outcome, tone, session_age_min, budget_remaining_pct}` deterministically (no LLM).
  - `pp_router_pick_lenses(signals, enabled_lenses) → array of lens_ids` — one gpt-5-mini call, returns 1–3 lens IDs from `enabled_lenses` that best match the signals. Bounded by `PP_ROUTER_MAX=3`.
  - `pp_router_surprise_inject(picked) → array` — with `PP_ROUTER_SURPRISE_PROB=0.2` probability, append one random *off-discipline* lens from the disabled pool (preserves the v0.3 serendipity property the user explicitly named in prior brainstorming).
- Create `prompts/router.md` — system prompt for the router LLM call. Inputs: signals JSON + lens registry (id + 1-line description). Output: JSON list of lens IDs.
- Modify `bin/statusline.sh`:
  - Before fan-out, call `pp_router_pick_lenses` and replace the `for lens in ${PP_LENS_IDS[@]}` loop with `for lens in $($router_output)`.
  - The router call itself is one extra LLM call per cycle but eliminates 4–6 fan-out calls — net negative cost.
- Modify `lib/budget.sh` — `budget_reserve` now reserves `1 (router) + N_picked + 1 (critique)` instead of `7 + 1`. Single source-of-truth invariant preserved.
- Modify `test/eval/eval.bats` — re-run, assert that *for sessions where a specific concern was the golden answer, the lens that owns that concern is picked at least 70% of the time*. This is a new metric: **routing accuracy**.
- Create `test/router.bats` — fixture-driven tests for signal detection (phase from tool-call patterns, frustration from text markers, etc.).
- Create `test/eval/fixtures/router-{01..05}.tar` — 5 new fixtures where the *correct* lens is known (e.g., a fixture with a test failure should route to a debugger-shaped lens).

**Gate:** Routing accuracy ≥70% on the 5 new fixtures; per-cycle cost drops ≥30% vs Phase 1 baseline.

**Risk:** Router false negatives — the security lens never fires on a UI-touching diff, but a hidden auth concern is in there. Mitigation: the 20% surprise inject is exactly this insurance policy. Tunable via `PP_ROUTER_SURPRISE_PROB`; can be raised to 0.3 if eval-gate detects lost catches.

`★ Architectural note:` the router is itself an LLM call, which means it can be wrong. The mitigation isn't "make it perfect" (impossible) but "make it cheap enough that being wrong 20% of the time is fine." gpt-5-mini @ ~$0.001/call means a wrong router decision costs less than a single lens analyst call. The economics work because we're trading a $0.05 fan-out for a $0.02 routed-fan-out + $0.001 router.

## Phase 3 — Dismiss + memory-as-constraint

**Why third:** the noise floor fix doesn't need the intelligence layer to land in front of it, but it makes the intelligence layer survivable. Once the router is picking voices and the filtered transcript is feeding them, a few will say wrong things — dismiss is the relief valve.

**Budget:** 3 work-days, 1 PR.

**Files:**
- Create `lib/dismiss.sh`. Functions:
  - `pp_dismiss_add(reason, scope=project|global, lens=optional)` — generates a rule (LLM-summarized canonical form), stores at `~/.claude/pair-polymath/dismiss/<project_hash>.jsonl`. Honors existing project-hash salt (`lib/memory/schema.sh:pp_memory_get_salt`).
  - `pp_dismiss_list(scope) → text`
  - `pp_dismiss_undo(id)` — soft-delete (kept for audit, marked inactive).
  - `pp_dismiss_render(project_hash) → text` — emits a constraint block for injection into analyst prompts.
  - `pp_dismiss_auto_suppress` — heuristic background pass: if same observation hash fires `PP_DISMISS_AUTO_THRESHOLD=5` times without being quoted in any user message, auto-add a 7-day TTL rule.
- Modify `bin/polymath`:
  - Add subcommands: `polymath dismiss <reason>`, `polymath dismiss list`, `polymath dismiss undo <id>`.
- Modify `prompts/analyst-primary.md` — add `${project_constraints}` placeholder near the top of the system prompt.
- Modify all `lenses/*.json` system prompts — append the canonical stanza (one sentence) at end of each `system_prompt`.
- Modify `lib/prompt-loader.sh` — register `project_constraints` in allowlist.
- Modify `bin/statusline.sh` — render constraints once per cycle, pass to all analyst subshells.
- Create `test/dismiss.bats` — coverage for add/list/undo, scope isolation (project A's rule doesn't suppress in project B), auto-suppress threshold.

**Gate:** Eval delta shows hallucination% drops on second-run-after-dismiss; no useful% regression. Test that auto-suppress fires correctly on synthetic repeated observation.

**Risk:** Over-suppression — a legitimate concern gets dismissed because it was loud once. Mitigation: 30-day default TTL on auto-suppressions; `polymath dismiss list` is the audit surface; `undo` is one command.

## Phase 4 — Foothold for v0.6 (categories + 5 new lenses + SessionEnd)

**Why last:** these are additive, low-risk changes that benefit from the intelligence layer being in place. New lenses get evaluated against the new router; categories get tested as the structure router queries.

**Budget:** 2 work-days, 1 PR.

**Files:**
- Restructure `lenses/` from flat to categorized:
  ```
  lenses/
    executive/
    development/   (existing engineering, security, perf-finops move here)
    product/       (existing ux-design, product-biz move here)
    meta/          (existing strategic-founder, cognitive-flow move here)
  ```
- Modify `lib/lens-loader.sh` — walk subdirectories. Cap `PP_LENS_MAX=16` preserved.
- Add 5 new lenses (JSON only):
  - `executive/cfo.json` — burn rate, ROI, unit economics
  - `meta/pre-mortem.json` — "imagine this shipped and failed, why?"
  - `meta/devils-advocate.json` — strongest counterargument
  - `meta/historian.json` — uses memory + git log to surface prior decisions
  - `development/database-engineer.json` — schema, queries, indexes
- Add `lenses/presets/solo-founder.json`:
  ```json
  { "id": "solo-founder", "lenses": ["executive/ceo-or-cto", "development/security-engineer", "meta/cognitive-flow", "meta/pre-mortem"] }
  ```
  (Will be a no-op until v0.6 install UI lands, but the file format is locked now.)
- Create `hooks/session-end.sh` (new SessionEnd hook). On session end: read per-lens caches for this session, call gpt-5-mini once to summarize into a single memory entry, write via `pp_memory_insert` with `kind="session_summary"`.
- Modify `settings.json.template` — add the SessionEnd hook wiring.
- Modify `lib/doctor.sh` — add check that SessionEnd is wired.
- Create `test/session-end.bats` — fixture session with N cached observations; assert that `pp_session_end` produces one memory entry.

**Gate:** All existing tests pass; eval-gate baseline unchanged (no regression from restructure).

## Cost model — net delta vs v0.3.0

Per-cycle accounting at default model selection (gpt-5-mini analysts, gpt-5 critique):

| Component | v0.3.0 | v0.4 |
|---|---|---|
| Planner call (1×) | $0.002 | $0.002 |
| Router call (new, 1×) | — | $0.001 |
| Analyst calls | 7 × $0.008 = $0.056 | 1–3 × $0.014 = $0.014–$0.042 (wider input) |
| Critique call (1×) | $0.005 | $0.005 |
| Retry budget (worst case) | $0.024 | $0.012 |
| **Per cycle worst-case** | **~$0.087** | **~$0.062** |
| **Per cycle typical** | **~$0.05** | **~$0.035** |
| Per active hour (12 cycles) | $0.60 typical | $0.42 typical |
| Per day heavy use (10h) | $6 | $4.20 |

**Net: −30% per-cycle cost** while the model sees ~3× more signal. The router's existence inverts the cost curve.

## Risk register

| Risk | Likelihood | Mitigation | Detector |
|---|---|---|---|
| Router suppresses the lens that would have caught X | High | 20% surprise inject; tunable | Eval-gate routing-accuracy metric |
| Filtered transcript drops critical tool output | Medium | `PP_TRANSCRIPT_TOOL_TRUNC` is per-user tunable; eval-gate regresses if so | Useful% delta in eval |
| Dismiss over-suppresses legitimate concerns | Medium | 30-day TTL on auto-suppress; explicit `undo` | `polymath dismiss list` audit |
| SessionEnd rollup hallucinates session content | Low | Single summarization call has bounded input (per-lens caches only); fails silent if budget exhausted | Memory entry length cap |
| Categorization breaks user-defined lens overrides | Low | `id` field still primary key; user `id` overrides built-in invariant preserved (from CLAUDE.md) | Lens-loader tests |
| Router adds latency before fan-out | Low | gpt-5-mini @ ~200ms; fan-out parallelism unchanged afterward | Cycle-time eval metric |

## Gate to v0.5 (auto-review)

v0.5 ships when v0.4 has been live for ≥2 weeks AND:
1. Eval-gate shows useful% ≥+10pp vs v0.3.0 baseline across ≥5 of 7 lenses
2. Per-cycle cost has not regressed past v0.3.0 worst-case
3. Dismiss usage data shows >0 rules created (proves the feature is reachable)
4. Routing accuracy on canonical fixtures ≥70%

Failing any gate, v0.4 gets a follow-up patch release (v0.4.1) before v0.5 work begins.

## What v0.4 explicitly does NOT promise

To prevent scope drift:
- It does **not** auto-review your code after task completion. That's v0.5.
- It does **not** add a multi-select install picker. That's v0.6.
- It does **not** add internet access to analysts. Deferred indefinitely.
- It does **not** ship 35 lenses. 12 (the existing 7 + 5 new) — taxonomy validation only.
- It does **not** add `polymath lens add` interactive authoring. That's v0.6.
- It does **not** rewrite anything in Python or any other language.

If during implementation any of these creep in, they get split into a separate PR and held for the appropriate version.
