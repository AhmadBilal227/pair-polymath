# v0.5.1 Tier 0 — Cost Cuts + Logging/Eval Foundation (Spec R0)

**Status:** Pass-2 of Ralph loop. Inputs: Pass-1 swarm (retry mechanism, phase classifier, investigation streak) + GPT 3-round critique of broader v0.5.x plan + user-specified "logging+eval in every phase."

**Goal:** Cut pair-polymath operational cost ~30-40% (data-grounded — retries are 84% of spend) while landing the observability foundation that v0.5.2 OAR depends on. Ship in **shadow → canary → full** sequence with auto-rollback.

**Out of scope:** Lens persona changes (v0.5.1.1), OAR labeler (v0.5.2), DIM (v0.5.3).

## Components

### A. Cost-aware retry router (`lib/retry-router.sh` new, ~150 LOC)

**What it does:**
- Classifies each critique DROP into a `retry_reason` taxonomy: `citation_fail | vague | redundant | stale | format | unknown`
- Computes a confidence proxy (drop-reason class + allowlist non-emptiness + body length + concurrent-drop count + lens streak)
- HIGH-confidence drops → retry at premium model (gpt-5)
- LOW-confidence drops → retry at base model (gpt-5-mini, 7× cheaper)
- Insertion point: `bin/statusline.sh:1246-1254` (between drop parse and retry render)

**Public API + explicit decision tree (GPT-R2 #8):**

```bash
pp_retry_classify_reason DROP_REASON_RAW
# Decision rules:
#   matches /citation|cite|hallucin|fabric|not in allowlist/i → citation_fail
#   matches /stale|already fixed|outdated|already addressed/i  → stale
#   matches /vague|no actionable|investigate|unspecific/i     → vague
#   matches /redundant|already|same as|duplicate/i            → redundant
#   matches /format|schema|invalid|malformed/i                → format
#   else                                                       → unknown

pp_retry_confidence REASON_CLASS ALLOWLIST_PATHS_N ALLOWLIST_SYMBOLS_N \
                    OBS_BODY_LEN LENS_STREAK CONCURRENT_DROPS
# Decision rules (high vs low):
#   HIGH iff:
#     REASON_CLASS == citation_fail AND (paths_n > 0 OR symbols_n > 0)
#       AND OBS_BODY_LEN >= 80
#       AND CONCURRENT_DROPS <= 2
#   (format errors default to LOW — they're cheap to retry on mini per GPT-R3 #4)
#   else → LOW
# Auditable: every input that flips the decision is in this rule set.

pp_retry_select_model CONFIDENCE         # echoes model name based on PP_RETRY_MODEL_HIGH/LOW
                                          # if PP_RETRY_MODEL user-pinned → echoes that (escape hatch)

pp_retry_log_shadow JSON_BLOB            # appends to retry-router-shadow.jsonl
                                          # silent fail (telemetry never blocks cycle)
                                          # honors PP_LOG_MAX_BYTES rotation

pp_retry_record_actual JSON_BLOB         # appends to retry-router-actual.jsonl (when ENABLE=1)
                                          # captures real model used + actual_usd
                                          # used by shadow-vs-actual eval comparison
```

**Critical flow (GPT-R2 #5):** Shadow logging runs INDEPENDENT of router behavior. When PP_RETRY_ROUTER_ENABLE=0 but PP_RETRY_ROUTER_SHADOW=1: classification runs, log written, retry proceeds with v0.5.0 model. When auto-rollback disables ENABLE: shadow keeps running so re-enable decision has fresh data.

**PII in shadow log (GPT-R3 #11):** Shadow log captures `drop_reason_raw` text from critique output. This text may contain user-visible paths/symbols (not raw secrets — the critique pass already operates on redacted grounded facts). For belt-and-suspenders: shadow log entries pipe through `pp_memory_redact_body` before write. Documented in `SECURITY.md` addendum that SHADOW is opt-in.

**Latency budget (GPT-R3 #12):** Adding the retry-router classifier + shadow log to the cycle's hot path must NOT regress p95 statusline wall-time by >30ms. CI perf test runs synthetic 100-cycle workload, asserts p95 delta ≤30ms vs baseline. `git status` cached once per cycle.

**Log rotation race-safety (GPT-R3 #6):** Rotation logic uses mkdir-lock + atomic mv. Test simulates 5 concurrent writers; assert no torn JSONL lines.

**Env knobs (config/default.env additions, ALL DEFAULT OFF):**
```bash
# Router behavior
PP_RETRY_ROUTER_ENABLE=0          # gate behavior change
PP_RETRY_ROUTER_SHADOW=0          # gate shadow logging (independent of ENABLE; opt-in)
PP_RETRY_ROUTER_CANARY_PCT=0      # 0=off, 10=canary, 100=full (only effective when ENABLE=1)
PP_RETRY_HARD_CAP_ENABLE=0        # gate hard-cap preflight (independent flag per GPT-R2 #3)

# Models
PP_RETRY_MODEL_HIGH=gpt-5
PP_RETRY_MODEL_LOW=gpt-5-mini

# SLO — ONE definition (GPT-R2 #1): rolling 24h of eligible cycles, p95 of retry_usd_per_cycle
# Eligible = NOT heavy_task (large estimated token in/out, special-lens-only cycles)
PP_RETRY_SLO_WINDOW_HOURS=24
PP_RETRY_SLO_P95_CAP_USD=0.030    # if p95 of eligible cycles' retry_usd > this, breach
PP_RETRY_SLO_MIN_SAMPLES=20       # min eligible cycles to compute p95; below = no SLO eval

# Hard preflight cap (kicks IN per retry call, before LLM call dispatched)
PP_RETRY_USD_PER_CYCLE_HARD_CAP=0.05

# Backoff (GPT-R2 #2 — single policy, no midnight)
PP_RETRY_BACKOFF_INITIAL_HOURS=24
PP_RETRY_BACKOFF_REPEAT_HOURS=72  # second consecutive disable extends to 72h
PP_RETRY_BACKOFF_MAX_HOURS=168    # third+ = 7d, then human-clear-only

# Log rotation (GPT-R2 #15 — applied to ALL new logs)
PP_LOG_MAX_BYTES=10485760
PP_LOG_MAX_AGE_DAYS=30

# Escalation
PP_ESCALATION_STREAK_THRESHOLD=3  # env-tunable; default 3 preserves v0.5.0 behavior

# KPI emitter (GPT-R2 #10 + R3 #2 — gated, BUT auto-enabled when router active)
PP_KPI_ENABLE=0                   # default off; AUTOMATICALLY treated as 1 when
                                  # PP_RETRY_ROUTER_ENABLE=1 OR PP_RETRY_ROUTER_SHADOW=1
                                  # (otherwise SLO/auto-rollback have no data source).
                                  # Override: PP_KPI_FORCE=0 to suppress even with router on.

# OAR/SessionEnd (v0.5.2 prereq)
PP_OAR_ENABLE=0                   # default off; SessionEnd hook no-ops when 0
```

### B. Phase classifier fallback (`lib/router-signals.sh` modify, ~40 LOC added)

**What it does:**
- When pattern-match returns `unknown`, runs 7-rule deterministic decision tree (F1-F7) using already-computed `_read_count`/`_edit_count`/`_test_with_pass` plus `git status --porcelain` (1s timeout)
- Emits new `phase_source: pattern|fallback|unknown` field in signals JSON

**Decision tree (Rules F1-F7 per Pass-1 swarm):**
- F1: empty inputs → honestly unknown (don't guess)
- F2: test_passed ≥1 + edits ≥1 → drafting
- F3: edits ≥1 + git_dirty → drafting
- F4: reads ≥3 + no edits + git_dirty → debugging
- F5: reads ≥2 + no edits + clean tree → planning
- F6: bash ≥3 + no test signal → planning
- F7: staged changes → drafting

**Schema additions:**
- Signals JSON: `+ "phase_source": "pattern" | "fallback" | "unknown"` (default "pattern" for backwards compat)
- `router-metrics.jsonl`: same field added; old records decode as "pattern"

### C. Investigation streak threshold env-tunable (`bin/statusline.sh:1049`)

**What it does in v0.5.1:**
- Promotes hardcoded `-ge 3` to env-tunable `-ge ${PP_ESCALATION_STREAK_THRESHOLD:-3}` (DEFAULT STAYS 3 — preserves byte-identity invariant; GPT-R1 #1)
- v0.5.1 is a no-op on actual behavior; v0.5.1.1 will raise default to 5 alongside lens persona changes (cleanly scoped behavior change)
- Per-Pass-1 empirical analysis: when raised to 5, cuts active escalations from 44/105 (42%) to 24/105 (23%) = 45% reduction

### D. SessionEnd hook scaffold (`hooks/session-end.sh` new, ~80 LOC) — GATED

**Why now:** Pass-1 flagged SessionEnd as prerequisite for v0.5.2 OAR. Smallest viable slice ships in v0.5.1 so OAR work is unblocked.

**What it does in v0.5.1 (when PP_OAR_ENABLE=1):**
- Reads Claude Code's `SessionEnd` event JSON from stdin
- For each `cc-monitor-injected-hash-<session>-<lens>.txt` of THIS session, writes an `oar-pending.jsonl` record with the hash, the inject time, and a "scan-at" timestamp
- Does NOT scan / classify yet — OAR labeler is v0.5.2

**Default behavior (PP_OAR_ENABLE=0 — DEFAULT per GPT-R1 #1):** hook script exits 0 immediately. Zero side effects. Byte-identity preserved.

**Registration:** `settings.json` adds `SessionEnd` hook entry pointing to `hooks/session-end.sh`. When flag is 0, the hook is invoked but is a no-op.

**Byte-identity test scope (GPT-R1 #15):** byte-identity test compares STATUSLINE STDOUT only, not file existence side effects. SessionEnd hook is invoked by Claude Code at session-end events that are out-of-band from statusline rendering.

### H. Auto-rollback (single SLO definition per GPT-R2 #1+#6)

**SLO computation (precise, no ambiguity):**
- Window: rolling `PP_RETRY_SLO_WINDOW_HOURS=24` of cycles
- Eligibility (v0.5.1 simplified per GPT-R3 #5): cycle is eligible iff `PP_RETRY_MODEL` is NOT user-pinned (escape hatch sessions excluded). Heavy-task token estimator deferred to v0.5.2 alongside OAR work — for v0.5.1, accept slightly higher SLO variance from heavy tasks. PR comment: "exclude pin, full v0.5.2 heavy-filter follows."
- Computation: `kpi-cycle.jsonl` is the source; filter to eligible cycles in window; compute `p95(retry_usd_per_cycle)`
- Min samples: if eligible count < `PP_RETRY_SLO_MIN_SAMPLES=20`, do NOT evaluate (avoid flapping on sparse data)
- Breach: `p95_eligible_retry_usd > PP_RETRY_SLO_P95_CAP_USD`

**Trigger:** SLO breach detected at cycle end → set flag with backoff TTL.

**Backoff state machine:**
```
state: { last_disable_ts, disable_count, next_check_ts }
```
- 1st breach in 30d: TTL = 24h (initial)
- 2nd breach within 30d of last clear: TTL = 72h (repeat)
- 3rd+ breach within 30d: TTL = 168h, doctor surfaces red, log loudly
- Always: shadow + KPI keep running during disable (data flows for re-enable decision)
- Clear: at flag-TTL OR via `polymath retry-router clear-flag` (resets disable_count to 0)

**New CLI surface (GPT-R1 #14):**
```
polymath retry-router shadow-summary   # rolls up retry-router-shadow.jsonl by drop_reason_class
polymath retry-router clear-flag       # manually clears auto-disable flag (resets backoff)
polymath retry-router status           # current state: enabled/disabled, canary %, flag age
```

### I. Canary cohort design (GPT-R1 #8 — formalized)

**Hash function:** `cksum <<< "${session_id}|${PP_RETRY_CANARY_SALT:-pp-canary-v1}" | awk '{print $1 % 100}'`
**Salt:** `PP_RETRY_CANARY_SALT` default `pp-canary-v1`; changing the salt resets cohort assignments (e.g. for new experiment)
**Stickiness:** same session_id always lands in same bucket across cycles → enables longitudinal session-level A/B
**Skew handling:** distribution monitored via `polymath retry-router status` showing actual cohort %; if observed % deviates >2pp from expected, log warning
**"session" definition:** session_id from Claude Code's stdin JSON (already used throughout pair-polymath)

### J. Hard cap preflight (GPT-R1 #4, #16)

**Per-retry price estimator** added to `lib/metrics.sh`:
```bash
pp_metrics_estimate_retry_usd MODEL   # echoes USD estimate for one retry call at this model
                                       # uses PP_AVG_TOK_RETRY_IN/OUT + price knobs already in default.env
```

**Cycle in-flight spend tally:**
- Per-cycle file `~/.claude/cache/retry-cycle-spend-${session_id}.txt` (mode 600)
- Mkdir-lock on increment (matches `lib/budget.sh:51-62` pattern)
- Cycle boundary = statusline cycle invocation; reset at cycle start
- Concurrent retries (parallel lens fan-out) acquire lock → preflight: `current_spend + estimated_retry_usd > HARD_CAP` → skip the retry, verdict stays DROP

### K. Phase fallback portability + caching (GPT-R1 #5, #9, #11)

**`git status` call:**
- Run ONCE per cycle (cached in shell variable, not re-invoked per-rule)
- Portable timeout: `gtimeout` if present, else mkdir-bg-kill pattern (per `lib/budget.sh` precedent); 1s ceiling
- Cache result in `_pp_git_dirty_cached` until next cycle
- On timeout/error → treat as `clean` (conservative fallback; never blocks classification)

**phase_source field default semantics (GPT-R1 #6):**
- New records always have explicit `phase_source` field
- Old records (no field) when consumed by KPI rollup: treated as `"unknown"` for delta computation purposes (NOT inflated as "pattern"). Doctor check + `polymath kpi` honor this rule.

### L. Quality guardrail metrics (GPT-R1 #10)

**KPI cycle schema additions:**
- `retry_acceptance_rate` — % of retries that produced PASS on resubmit
- `verdict_total_drops` — count of DROPs this cycle (proxy for noise)
- `cycle_outcome` — `success|partial|failure` derived from analyst-fan-out final state

**Why:** cost cuts that come at the price of quality regressions are net-negative. These metrics let canary decisions weigh both axes.

## Invariants (must hold)

1. **Off-by-default STDOUT-identity** (GPT-R2 #10 refinement): with all `PP_RETRY_ROUTER_*` + `PP_KPI_ENABLE` + `PP_OAR_ENABLE` = 0, `bin/statusline.sh` STDOUT is byte-identical to v0.5.0 on fixture inputs (sha256-asserted via bats). Side effects (new file writes) DO occur if SHADOW=1 or other opt-in flags set; that's their purpose.
2. **Shadow log NEVER blocks**: telemetry write uses `2>/dev/null || true` (precedent: `lib/router.sh:305-307`).
3. **Budget reservation unchanged**: worst-case 23-call cycle budget at `bin/statusline.sh:711` stays the same; the router REDUCES spend, doesn't add calls.
4. **Critique parser unchanged**: `^lens${ci}:` regex (`bin/statusline.sh:1216`) and retry output validation (`bin/statusline.sh:1272`) stay byte-identical.
5. **PP_RETRY_MODEL escape hatch**: if user has explicitly set `PP_RETRY_MODEL` in user.env, that pin wins over canary routing (escape hatch — they want a specific model).
6. **Fail-open**: any error in retry-router classification → fall through to v0.5.0 behavior. Never block a cycle.
7. **Auto-rollback never destructive**: flag file ONLY suppresses new behavior; no state mutation.
8. **Phase classifier ≤30ms wall budget**: `git status --porcelain` with 1s timeout; failure → empty result → falls through to F-default unknown.
9. **Lint-enforced env-var stability**: shell-grep CI step ensures any rename of a `PP_RETRY_*` env requires an explicit migration test.
