## Reframe

The earlier framing — "sharpen the personas" — turned out to be the wrong target. v0.5.2 just shipped the OAR foundation and the 26-cycle data from this session shows the real symptom:

| Lens | DROP rate this session |
|---|---:|
| UX_DESIGN | 81% |
| PRODUCT_BIZ | 81% |
| ENGINEERING | 72% |
| PERF_FINOPS | 72% |
| STRATEGIC_FOUNDER | 72% |
| SECURITY | 63% |
| COGNITIVE_FLOW | 63% |

Dominant DROP reasons (eyeballed from `~/.claude/cache/cc-monitor-*-verdict.txt`):

1. `"DROP — ungrounded"` / `"X not shown in facts"` — lens hallucinated.
2. `"DROP — citation fails: <file> not in allowlist"` — lens cited a path the validator didn't have on its allowlist (drift between what the lens sees and what the validator checks).
3. `"DROP — no observation provided"` — lens went empty without producing the SILENT sentinel.

GPT-5 coworker review summary (`/tmp/v0.5.1.1-gpt-review.md`): *"You're blaming personas, but the drops are a plumbing artifact: you fan out lenses with no eligible surfaces and the evaluator rejects both missing citations and non-observations — so you're measuring grounding/validator mismatch, not persona quality."*

**Decision:** v0.5.1.1 fixes the plumbing first. Persona work moves to v0.5.1.2 (after this lands and stable drop rates can be measured).

---

## Goals

1. Drop rate across all 7 lenses moves from the current 63-81% band into the 30-50% band **with zero changes to persona text**. The remaining drops should be real critique catches, not plumbing artifacts.
2. SILENT becomes a first-class outcome. A lens that legitimately has nothing in-scope to say is not penalised.
3. The validator's `VALID SYMBOLS` set is sourced from the same inventory the lens sees in its prompt — drift between the two is eliminated by construction.
4. Lenses that require user-facing surfaces (UX_DESIGN, PRODUCT_BIZ) are not dispatched when the session has no user-facing surface to observe.

Non-goals (deferred to v0.5.1.2):

- Editing persona text in `lenses/0N-*.json`
- A/B variant infrastructure
- Offline replay harness for principled variant comparison
- Persona-side strategy work (e.g., reframing UX_DESIGN to be less editorial)

## Three changes

### Change 1 — SILENT is first-class

**Today:** `bin/statusline.sh:1190` treats SILENT as "don't overwrite — keep previous valid observation." But the verdict file gets written before SILENT is recognised, so the critique pass scores SILENT as `DROP — no observation provided`. The OAR labeler, when it ships in production, will then score these as `ignored` even though the lens correctly identified nothing to say.

**Fix:**
- Recognise SILENT at the analyst-output level, **before** critique runs.
- New verdict reason: `SILENT — lens had no eligible surface (not a failure)`.
- SILENT is excluded from DROP rate calculations.
- OAR labeler treats SILENT rows as outcome=`silent`, distinct from `ignored`.

**Risk:** lens learns to abuse SILENT to dodge critique. Mitigation: SILENT requires `silent_reason` field for the new outcome (lens names which surface category was absent: `ui|copy|sec|perf|etc`). Validator checks `silent_reason ∈ {expected categories for this lens}`.

**[R1 P2 — SILENT abuse trend]** Track `silent_share_per_lens_7d` rolling. Doctor surfaces yellow if any lens crosses 80% SILENT for 7 consecutive days — that's the signal the persona has stopped trying. This is a TELEMETRY-ONLY signal in v0.5.1.1; no auto-action.

**[R3 — per-session SILENT cap CUT from v0.5.1.1.]** GPT round-3 flagged this as "the riskiest/least necessary for plumbing" — it requires defining session identity + persistence + cross-process state and introduces a forced-dispatch code path that itself can regress. Cut. Deferred to v0.5.1.2 (where it can be designed against real abuse data instead of speculation). The `silent_share_per_lens_7d` doctor signal above is the v0.5.1.1 substitute — operator alarm, no automatic action.

**[R2 P2 — closed enum]** `silent_reason` is a **closed enum per-lens**, declared in `lenses/0N-*.json` under `silent_reasons: ["no_ui_surface", "no_copy_change", ...]`. Validator rejects analyst output whose `silent_reason` is not in the lens's declared enum. Freeform reasons would trash the abuse alarm and SILENT-by-reason analytics.

### Change 2 — Validator's symbol allowlist is unified with the lens's symbol inventory

**Today:** the lens sees `SYMBOL REFERENCE COUNTS` (`bin/statusline.sh:855`, grep-derived). The validator sees `VALID SYMBOLS` (`bin/statusline.sh:1244`, FILE-READ-derived). The two sets often diverge — the lens cites something it grep'd from cwd, the validator drops because it's not in the FILE READ inventory.

**[R1 P0 — direction locked] Single source = FILE-READ-derived.** The grep set is broader than FILE-READ and includes symbols the model never actually saw in context; if we unified the OTHER direction, the validator would legitimize hallucinated citations. So:

**Fix:**
- `pp_grounding_symbol_inventory <facts_file>` returns the FILE-READ-derived canonical set. Used by both the lens prompt's `SYMBOL REFERENCE COUNTS` block AND the critique allowlist.
- Grep hits become a separate `NEARBY MENTIONS (NOT CITABLE)` block in the lens prompt — visible as orientation, explicitly marked non-citable. Lens that wants to cite a grep-hit must first pull it into a FILE READ (the planner's existing read affordance).
- **[R1 P1 + R2 P0 — split hashes]** every analyst+critique pair stamps TWO hashes into the verdict:
  - `canonical_allowlist_sha8` — hash of the full FILE-READ-derived symbol set. **drift_count invariant runs on this**: prompt-side and validator-side canonical hashes MUST be identical (it's the same source). If ever non-identical, the inventory pipeline has split — doctor surfaces red.
  - `rendered_prompt_sha8` — hash of the top-N symbols actually rendered to the lens. Separate KPI `render_truncation_count` increments when `canonical_size > N` (the model saw a subset; observability for whether top-N is large enough).
- **[R1 P2 + R2 P2 — token tax + sort spec]** Render top-N (default 80) symbols. **Sort order:** descending by reference count (the grep frequency the lens already sees in SYMBOL REFERENCE COUNTS). **Tie-break:** ASCII-lexicographic on symbol name. Determinism mandatory — required for hash stability across cycles with identical inputs. If `canonical_size > N`, append `(+N more — pull via FILE READ to cite)`.

**[R1 P0 + R3 — empty-allowlist mirrored via shared helper]** EMPTY-ALLOWLIST EXCEPTION at `prompts/critique.md:40` is preserved. When FILE-READ inventory is empty (cycle picked a non-source file), critique falls back to "any reasonable path cite OK." Both prompt and validator MUST mirror via single helper `pp_grounding_inventory_is_empty <facts_file>` (boolean) that BOTH read at render time. Prompt block renders the literal text `(no FILE-READ symbols extracted; cite by path only)` when helper returns true. Validator block renders the verbatim EMPTY-ALLOWLIST EXCEPTION clause. Bats regression test pins: identical fixture → both render their respective empty-state text → critique's accept-path-cite-only fallback fires. Without the shared helper, two engineers would write different `[ -z "$x" ]` vs `[ "$count" -eq 0 ]` checks.

### Change 3 — Planner gates: don't dispatch a lens that has no eligible surface

**Today:** `pp_router_pick_lenses` (`lib/router.sh:63`) picks ~3 lenses per cycle based on phase signals (planning/drafting/debugging). It does not check whether the picked lens has anything domain-relevant in the grounded facts. UX_DESIGN gets dispatched in a pure-shell-scripts cycle and dutifully reaches for "Jakob's law" + "personas buried in lens JSON" — both correctly DROPped.

**Fix:**
- Each lens JSON gains an `eligibility` block. **[R1 P0 — snapshot boundary]** eligibility is computed against the **cycle-start facts snapshot only**: `(FILE-READ paths) ∪ (git diff --name-only HEAD at cycle start, captured into the facts file)`. Never live FS, never post-dispatch inventories — both would race with the cycle. Snapshot is the same artifact the lens sees and the validator checks; eligibility is the third consumer of it.

  ```json
  "eligibility": {
    "any_of": [
      { "kind": "path_glob", "globs": ["**/*.tsx", "**/*.jsx", "**/components/**", "**/screens/**"] },
      { "kind": "path_glob", "globs": ["**/*.{css,scss}", "**/styles/**"] },
      { "kind": "path_glob", "globs": ["**/*.{md,mdx}", "**/copy/**"] }
    ]
  }
  ```

- New helper `pp_lens_is_eligible <lens_id> <facts_file>` returns 0/1 by matching `any_of` rules against the snapshot's path set. `kind: path_glob` is the only kind in v0.5.1.1 — `kind: phase` and `kind: signal` are reserved for v0.5.1.2.

  **[R2 P2 — glob semantics, locked]:**
  - Root: paths are repo-relative (the facts file already normalises this). Globs match against repo-relative form. No `/`-prefix on patterns.
  - Symlinks: not followed for glob matching. We compare the path string, not the resolved target.
  - Case-sensitivity: case-SENSITIVE matching (matches git semantics; HFS+/APFS case-folding handled at containment layer, not here).
  - Separators: POSIX `/` only. Windows paths not supported (pair-polymath ships macOS/Linux/Alpine only — already a project invariant).
  - Ignored dirs: globs that match `node_modules/`, `.git/`, `build/`, `dist/`, `target/`, `.cache/` paths are ignored automatically (so a lens with `**/*.json` doesn't fire on `node_modules/**/package.json`). Hardcoded list at this version; configurable in v0.5.1.2 if needed.
  - Binary files: excluded by default via the same heuristic the FILE-READ block uses (NUL-byte sniff in first 512 bytes).
  - Snapshot path set = **FILE-READ paths ∪ git changes**, where "git changes" = `git diff --name-only HEAD` + `git ls-files --others --exclude-standard` (untracked) + staged files (`git diff --cached --name-only`). This addresses [R2 P2] — pure-untracked work would otherwise underfire eligibility. HEAD semantics: detached HEAD is treated as HEAD. Dirty index counted via the staged + untracked union above.
  - **[R3 — gitless fallback]:** if `git rev-parse --git-dir` fails (CI sandboxes, archived tarballs, tests in `mktemp -d`), the `git_*` blocks are empty arrays and snapshot path set = **FILE-READ paths only**. Eligibility evaluator must NOT crash on a gitless cwd; bats regression test pins this.
  - **[R3 — glob engine pinned, bash 3.2 portable]:** new helper `pp_lens_glob_to_regex` converts each glob to an ERE regex ONCE at lens-load time (cached per-lens). Matcher uses bash 3.2's `[[ "$path" =~ $regex ]]` (no `globstar`, no `extglob`, no third-party tools — preserves project's bash 3.2 invariant). Conversion table:

    | Glob | Regex |
    |---|---|
    | `**/` | `(.*/)?` |
    | `**` | `.*` |
    | `*` | `[^/]*` |
    | `?` | `[^/]` |
    | `{a,b,c}` | `(a\|b\|c)` |
    | `.`, `+`, `(`, `)`, `[`, `]`, `^`, `$`, `\|` | escaped (literal) |
    | everything else | literal |

    Anchored `^…$`. Negation NOT supported (use lens's `silent_reasons` to opt out instead of inverse glob). Paths with spaces handled (regex is character-set based, not word-splitting). Test fixture pins 8 cases per the glob form examples; conversion table itself is unit-tested (golden file fixture). Bats regression test asserts conversion stability — any future tweak to the converter must update the golden file.
- `pp_router_pick_lenses` filters picks through eligibility BEFORE counting against its 3-lens-per-cycle quota. **[R1 spec bug]** if a picked lens is ineligible it's dropped from the pick (not dispatched + auto-SILENT) — otherwise the auto-SILENT bookkeeping eats the budget. Replacement candidate is drawn from the next-ranked eligible lens. If `< 3` eligible lenses exist, fan-out runs smaller.
- ENGINEERING / SECURITY / PERF_FINOPS use broad code globs (most cycles touch code). UX_DESIGN / PRODUCT_BIZ get narrower globs (UI files, copy, public assets, snapshots).

- **[R1 P0 — STRATEGIC_FOUNDER + COGNITIVE_FLOW]** these observe meta-state, not files. v0.5.1.1 ships them with `"any_of": [{"kind": "always"}]` (always eligible) and **drops AC #2 for them** — their SILENT rate will be low because they have no file-eligibility gate, so their drops can only come down via persona work in v0.5.1.2. Acceptance bar for these two lenses tightens in v0.5.1.2 once `kind: phase` / `kind: signal` ship.

**Risk:** mis-gated lenses go quiet on cycles that would have produced a real catch. **[R1 P1 — PASS-at-risk]** shadow mode logs `would_be_ineligible: bool` on every PASS observation. Doctor surfaces `pass_at_risk_rate` per lens. Activation gated on `pass_at_risk_rate < 5%` per lens for 48 consecutive hours.

## Schema versioning

**[R2 P1 — schema versioning]** v0.5.1.1 introduces new fields across three on-disk artifacts. Each gets a version bump so downstream consumers (OAR labeler, polymath history, doctor) can be tolerant of mixed-version reads:

| Artifact | Pre-v0.5.1.1 | v0.5.1.1 | New fields |
|---|---|---|---|
| `cc-monitor-*-verdict.txt` | (no version) | `schema_version: 2` | `silent_reason`, `canonical_allowlist_sha8`, `rendered_prompt_sha8` |
| `oar-pending.jsonl` row | `schema_version: 1` | `schema_version: 2` | (none added in row; new `outcome=silent` value tolerated by labeler) |
| `oar-labeled.jsonl` row | `schema_version: 1` | `schema_version: 2` | `outcome: silent` (new enum value), `silent_reason`, `would_be_ineligible` (shadow only) |
| `metrics.jsonl` cycle row | `schema_version: 1` | `schema_version: 2` | 7 new fields: `eligible_count`, `dispatched_count`, `silent_count_by_reason`, `pass_count`, `drop_count`, `drift_count`, `would_be_ineligible_count` |
| Facts snapshot (`cc-monitor-facts-*.txt`) | (no version) | `# facts_schema: 2` (header) | `git_diff_paths`, `git_untracked_paths`, `git_staged_paths` blocks added |

**[R3 — dual-write migration, NOT read-tolerance.]** The previous "readers accept schema_version ≤ compiled" rule was backwards for real upgrades — old binaries can't promise forward compatibility. Corrected approach:

- **v0.5.1.1 WRITERS emit BOTH schemas:** verdict/KPI/labeled writers emit a row that is v1-valid AND includes the v2-only fields. A v0.5.1.0 reader sees the row's v1 fields and ignores the unknown keys (JSON line readers tolerate extra keys; verdict text format gets v2 fields APPENDED with `# v2:` prefix that v1 parsers ignore as a comment).
- **v0.5.1.1 READERS accept v1 + v2 rows:** OAR labeler treats absent `silent_reason` / unknown outcome as `ignored` (legacy fallback). polymath history defaults missing v2 fields to neutral values (0 or empty).
- **Cutover:** once doctor confirms all on-disk rows are v2 (typically after 30 days of log rotation), v0.5.1.2 can drop the v1-compatibility shim. The schema_version field stamps every row so readers can route per-row.
- **Tests:** upgrade-path bats fixtures with: (a) v1 reader consuming first-cycle-post-upgrade v2 artifact, (b) v2 reader consuming pre-upgrade v1 artifact. Both must pass cleanly.

## Acceptance criteria

Empirical, measurable after 24-48h of cycles with PP_LENS_GATES_ACTIVE=1. **[R1 P1 — coverage metrics]** KPI emitter extended to record these per cycle per lens:

```
eligible_count          (1 if lens passed eligibility gate)
dispatched_count        (1 if actually invoked — may be 0 if pick budget exhausted)
silent_count_by_reason  { no_eligible_surface, persona_silent }
pass_count              (1 if survived critique)
drop_count              (1 if dropped by critique with reason category)
drift_count             (1 if prompt_symbols_sha8 != allowlist_symbols_sha8 — invariant)
would_be_ineligible     (PASS-at-risk counterfactual during shadow only)
```

**[R2 P2 — denominator clarification]** All counts are **per lens per cycle, integer 0 or 1**. `eligible_count` is not "number of eligible files"; it's "1 if this lens was eligible this cycle, 0 otherwise." This avoids the obvious mis-reading.

From these, all ACs are derivable. **[R2 P0 — explicit lens carve-outs]**:

| AC | Applies to | Excluded |
|---|---|---|
| #1 DROP_excl_silent −30pp | UX_DESIGN, PRODUCT_BIZ (hard bar) | STRATEGIC_FOUNDER, COGNITIVE_FLOW (no glob signal; v0.5.1.2 bar) |
| #2 SILENT rate non-zero | UX_DESIGN, PRODUCT_BIZ | STRATEGIC_FOUNDER, COGNITIVE_FLOW |
| #3 drift_count = 0 | ALL lenses (invariant) | none |
| #4 PASS rate within ±10% | ALL lenses with `kind: path_glob` | STRATEGIC_FOUNDER, COGNITIVE_FLOW (kind: always — no eligibility change to measure) |
| #5 Coverage ≥80% | ENGINEERING, UX_DESIGN, SECURITY, PERF_FINOPS, PRODUCT_BIZ | STRATEGIC_FOUNDER, COGNITIVE_FLOW (always eligible by design — coverage =100% trivially) |

1. **DROP_excl_silent ratio drops by ≥30 pp on UX_DESIGN + PRODUCT_BIZ.** Formula: `drop_count / (dispatched_count − silent_count_total)`. Target: <50% post. Method: 7d pre (`PP_LENS_GATES_*=0`) vs 7d post (`PP_LENS_GATES_ACTIVE=1`) via `polymath kpi --lens UX_DESIGN`. ENGINEERING + SECURITY + PERF_FINOPS expected to improve too but no hard bar — Change 2 (inventory unification) is the lever there, not Change 3.
2. **SILENT rate per lens is non-zero** for UX_DESIGN + PRODUCT_BIZ (proves Change 3's `no_eligible_surface` path is reachable in real cycles).
3. **drift_count = 0 across all cycles for 7 consecutive days.** Doctor surfaces yellow on any non-zero. This is the runtime guarantee that the static bats regression is augmenting. Drift invariant runs on `canonical_allowlist_sha8` (full set, not the rendered subset).
4. **PASS rate per dispatched-non-silent invocation stays within ±10% of baseline.** Formula: `pass_count / (dispatched_count − silent_count_total)`. **[R1 P1]** during shadow, the counterfactual `pass_at_risk_rate = (pass_count AND would_be_ineligible) / pass_count` per lens with `kind: path_glob` must read <5% before activation — proves eligibility won't kill real catches.
5. **Coverage** = `(dispatched_count − silent_count_total) / eligible_count` stays ≥80% per lens (with the per-AC carve-outs above) for 7d. Catches the failure mode where eligibility fires but the persona then SILENTs everything.

## Rollout

Same shadow-by-default pattern as v0.5.2:

1. **Shadow (1 week):** `PP_LENS_GATES_TELEMETRY=1` only. All 7 new KPI fields emit per cycle. Eligibility evaluated and `would_be_ineligible` stamped on PASS observations; behavior unchanged. Dual-write schema cuts in: writers emit v1 + v2 fields concurrently. drift_count alarm (doctor #22) live.
2. **Inspect:** `polymath kpi --lens <id>` shows projected SILENT rate per lens, `pass_at_risk_rate` (would-have-been-ineligible PASS count / total PASS), and drift_count = 0 invariant. Activation gated on `pass_at_risk_rate < 5%` per lens with `kind: path_glob` for 48 consecutive hours.
3. **Activate Stage B+C (1 week):** flip `PP_INVENTORY_UNIFY_ACTIVE=1` (prompt → FILE-READ-only block; grep hits move to NEARBY MENTIONS) and `PP_SILENT_V2_ACTIVE=1` (SILENT recognized pre-critique; OAR labels `outcome=silent`). These are the correctness improvements; expected to drive most of the drop-rate reduction.
4. **Measure:** if `DROP_excl_silent` on UX_DESIGN + PRODUCT_BIZ drops by ≥30pp from this alone, activation of Change 3 (Stage D) may be optional. Re-evaluate after 72h.
5. **Activate Stage D if needed (1 week):** add `PP_LENS_GATES_ACTIVE=1`. Eligibility now filters picks (Change 3 enforced); SILENT-with-reason emitted on `no_eligible_surface`.
6. **Final measure:** acceptance criteria 1-5 above.

**[R1 P1 + R3 — per-flag auto-rollback gates]** Each kill-switch has independent rollback conditions; tripping ONE only reverts that flag, others stay on for diagnosis:
- `PP_INVENTORY_UNIFY_ACTIVE` auto-reverts if: drift_count > 0 (inventory pipeline bug), OR PASS rate drops > 15% within 24h (FILE-READ-only is too restrictive).
- `PP_SILENT_V2_ACTIVE` auto-reverts if: any silent_reason fails enum validation > 1% of attempts (analyst learned to break the contract), OR OAR labeler crashes parsing v2 outcome rows.
- `PP_LENS_GATES_ACTIVE` auto-reverts if: `pass_at_risk_rate` observed >10% in any single 24h window post-activation, OR Coverage drops <70% on any path_glob lens, OR DROP_excl_silent INCREASES by >5pp on any lens vs the shadow baseline.
