# v0.5.2 — OAR Foundation + Hallucination Gate + `polymath history` CLI

**Status:** DRAFT v4 — LOCKED (post GPT-5 round 3; resolves 10 spec-internal contradictions / undefined helpers / unbounded windows)
**Target:** Ship the measurement substrate that gates v0.5.3 (DIM)
**Prereq:** v0.5.1.0 shipped (SessionEnd hook scaffold lives at `hooks/session-end.sh`; deterministic citation allowlist lives at `lib/citations.sh` + `prompts/critique.md`)
**Off-by-default:** All new behavior gated on `PP_OAR_ENABLE=0` and `PP_HALLUC_GATE_ENABLE=0`; byte-identity to v0.5.1 holds.

## The metric this release is for

**OAR (Observation → Action Rate)** classifies each injected advisory's next-N-hours outcome into one of four buckets. Two of them — `acted` and `referenced` — are reported **separately** in CLI output; the derived sum is shown as "A+R" but never as the primary signal, because "talked about it" ≠ "did it" and OAR's value is in the disaggregation, not the headline number.

| Outcome | Definition (deterministic) | Evidence |
|---|---|---|
| `acted` | A post-injection git diff hunk **contains a cited symbol or hunks overlap a cited path-line-range**, with renames tracked. | The diff-hunk content must include at least one of: an exact symbol token from the observation (word-boundary match, stopword-filtered, minimum length 4 to avoid common-identifier false-positives), OR a `+/-` line within ±20 of the cited line range. Renames are tracked via `git log --follow --diff-filter=AMRC -M50% -- <path>` then `git show -M50% <commit>` on each touching commit. NOT mere file-touch. |
| `referenced` | Token-bigram Jaccard overlap between filtered transcript user-turns (post-inject) and observation body ≥ `PP_OAR_REF_TAU` AND ≥1 cite-token from the observation appears in the user-turn. | Stopword-filtered (reusing `lib/citations.sh::PP_CITATION_STOPWORDS`). Require cite-token presence to prevent inflated overlap on common phrasing. |
| `pushed-back` | `polymath dismiss ack <hash-prefix>` was invoked for this hash between `inject_ts` and `min(now, scan_at_epoch)` — i.e. within the scan window. | Explicit operator action only — **no transcript-negation heuristic**. (Sentiment-based pushback detection deferred to v0.5.3 after we have ground-truth labels to validate against.) |
| `ignored` | Window elapsed with no `acted`, `referenced`, or `pushed-back` signal. | Default classification. **Framing caveat:** an ignored row is "no evidence within window" — NOT "no value." Long-horizon advisories may be acted on later (v0.5.3 will add a late-acted reclassification pass). |

OAR is the **read-only measurement substrate** that v0.5.3 (DIM) uses for fidelity gating. v0.5.2 does NOT automate any rollout decision based on OAR — it only ships the data.

## Architecture (Sections A through H)

### A. Data flow

```
Cycle N:    inject-monitor-insight.sh  →  cc-monitor-injected-hash-${sid}-${lens}.txt (mtime = inject ts)
            statusline.sh              →  cc-monitor-${sid}-${lens}.txt (observation body, the cited content)

SessionEnd: session-end.sh             →  oar-pending.jsonl
                                            {sid, lens, hash, inject_ts, scan_at_epoch,
                                             attempts:0, status:"pending"}

Cycle N+k (after scan_at):
            lib/oar.sh::pp_oar_label_pending  → oar-labeled.jsonl
                                                  {sid, lens, hash, inject_ts, labeled_at,
                                                   outcome,            // acted|referenced|pushed-back|ignored
                                                   evidence_id,        // full 40-char commit SHA, "line:NNN-MMM" tail-file range, dismiss rule_id, or null
                                                   confidence,         // STRING label — see Sec B (symbol_exact|line_proximity|jaccard:0.NN|exact|no_signal_in_window). NOT a 0-1 float.
                                                   evidence:{...}}
            On unrecoverable failure (3 attempts): → oar-stuck.jsonl, surfaced in doctor #20.
```

**No background process.** Labeler runs **inline on the next statusline cycle** that observes due rows.

### B. The OAR labeler — `lib/oar.sh::pp_oar_label_pending`

For each pending row with `scan_at_epoch < now()`:

1. **acted?** — Run `pp_contain_path` on every cited path (containment check; reject rows that cite outside cwd). **Per cited path** (not multi-path — `git log --follow` only honors a single pathspec): `git log --since="@${inject_ts}" --until="@${scan_at_epoch}" --follow --pretty=format:%H -- "${escaped_path}"`. Path is shell-quoted and passed after `--` (git pathspec separator) — see helper `pp_safe_git_pathspec` (Sec B.1). For each touching commit, `git show -M50% --unified=0 <commit> -- "${escaped_path}"` (the rename-tracker flag `-M50%` lives on `git show`/diff, not `log`). Check the diff content: includes any cited symbol token (stopword-filtered, word-boundary regex, min token length 4) OR a `+/-` line within ±20 of the cited line range. If yes → outcome=acted, `evidence_id=<full-40-char-SHA>`, confidence=`symbol_exact` (string label) or `line_proximity`.
2. **pushed-back?** — Read `~/.claude/state/dismiss-rules.jsonl`; if a rule with `source=ack` and `hash_prefix` matching this row's hash, with rule's `created_at` in window `[inject_ts, min(now, scan_at_epoch)]`, exists → pushed-back. `evidence_id=<rule_id>`, confidence=`exact`.
3. **referenced?** — Read `~/.claude/cache/transcript-tail-${sid}.txt`; extract user-turn segments with timestamps in window `[inject_ts, min(now, scan_at_epoch)]` (BOTH bounds — no late-reference leakage); compute stopword-filtered token-bigram Jaccard against observation body; if ≥`PP_OAR_REF_TAU` (default 0.5) AND ≥1 cite-token appears in the user-turn → referenced. `evidence_id="line:${line_start}-${line_end}"` (line range within the tail file at labeling time; **known limit:** line numbers shift if the tail file is later truncated — evidence is "best effort, point-in-time"). Confidence=`jaccard:0.NN` (the score as a string-tagged value, not asserting probability).
4. **ignored** — default if none above. `evidence_id=null`, confidence=`no_signal_in_window` (NOT "1.0" — transcript truncation and label cap can miss signal; the label means "no signal found within our bounded scan").

#### B.1 `pp_safe_git_pathspec`

New helper in `lib/grounding.sh`. Takes a contained path and emits a single-quoted, pathspec-safe string suitable for `git ... -- "$(pp_safe_git_pathspec "$p")"`. Strips trailing slash, escapes single quotes, prepends `:(literal)` magic to disable git's own globbing. Distinct from `pp_safe_grep_pattern` which is for grep regexes. Tests in `test/grounding.bats`.

**Identity & idempotency.** A row's stable identity is `sha256(sid|lens|hash|inject_ts)` — `inject_ts` is part of the key so that re-injections of the same `(sid, lens, hash)` triplet at different cycles don't collide and silently drop. Labeled rows are appended to `oar-labeled.jsonl` and removed from `oar-pending.jsonl`. Running the labeler twice on the same identity is a no-op (labeled set membership check).

**Backoff & quarantine.** Each labeler attempt that errors increments `attempts`. After `PP_OAR_LABEL_MAX_ATTEMPTS=3` failed attempts, the row moves to `oar-stuck.jsonl` with the last error message. Doctor check #20 surfaces stuck-row count.

**Timeout handling.** Per-row labeling has a soft cap of `PP_OAR_ROW_TIMEOUT_S=3` seconds (bumped from the v3 spec's implicit 1s; mono-repo `git log/show` over many commits can exceed 1s legitimately). On timeout: leave the row in pending, increment `attempts`, move on. The PER_CYCLE_CAP (5 rows) × timeout (3s) gives a worst-case 15s cycle, but the cycle's 5min interval makes that a non-issue. `polymath oar-label --all-due` uses the same per-row timeout but no per-cycle cap.

**Containment.** Cited paths go through `pp_contain_path` BEFORE being passed to `git log -- ...`. The shell-escape for git is handled by the existing `lib/grounding.sh::pp_safe_grep_pattern`-equivalent for path args.

**Per-cycle cap.** `PP_OAR_LABEL_PER_CYCLE_CAP=5` rows max per statusline cycle. **Scheduling: FIFO by `scan_at_epoch` ascending** — oldest-due rows first, so window-compliance is preserved and no row starves indefinitely. If backlog exists, `polymath oar-label --all-due [--limit N]` (Section D) is the manual catchup.

### C. Hallucination gate — shadow-only in v0.5.2 (avoids OAR measurement contamination)

**Critical change from v2:** GPT round-2 caught that the v2 post-check, by flipping critique-PASSED observations to DROP, would shrink the OAR denominator silently when both features are enabled. The observation never reaches the user → never queued for labeling → A/R rates measured on a biased subset. Measurement substrate and gating logic must not be entangled.

**v0.5.2 ships hallucination gate in SHADOW MODE ONLY** — same pattern as v0.5.1's retry-router. The post-check runs and emits telemetry, but does NOT flip any verdict. This lets us measure the post-check FPR vs OAR data BEFORE we decide to gate on it.

v0.5.0 ships a deterministic citation allowlist (`lib/citations.sh` + `prompts/critique.md`). v0.5.2 adds:

- **Telemetry split.** Two new counters:
  - `halluc_pre_drop`: critique pass DROPped the observation with reason class `citation_fail` (allowlist mismatch caught by the critique LLM). Already classified by retry-router.
  - `halluc_post_would_drop` (SHADOW): `pp_halluc_verify_citations` ran on a critique-PASSED observation and would have flipped it to DROP. **The actual verdict is NOT changed.** The observation still ships to the user, still enters the OAR pipeline. The telemetry counter is emitted for FPR analysis.
  Both surfaced in `polymath kpi` as separate `halluc_pre_drop_rate` and `halluc_post_would_drop_rate`.
- **Deterministic post-check (shadow).** `lib/hallucination.sh::pp_halluc_verify_citations` runs AFTER critique PASS on each observation. Re-checks every cited path/symbol using stricter rules than the critique LLM: path canonicalization (`realpath` containment), symbol-token exact match (word-boundary regex, no basename-collapse), with optional ctags fallback if `PP_HALLUC_GATE_DEEP=1`. **If a PASS observation fails the post-check → verdict UNCHANGED, telemetry emitted, observation still injected.**
- **Active mode (`PP_HALLUC_GATE_ACTIVE=1`)** flips post-check failures to actual DROPs. Default off. We need post-check FPR data first.

This ordering — shadow first, active mode behind a flag, hard-fail deferred to v0.5.3 — keeps OAR measurement valid in v0.5.2 (no contamination) and gives us the empirical basis for the v0.5.3 gating decision.

### E. Env knobs (all OFF/baseline by default)

| Knob | Default | Effect |
|---|---|---|
| `PP_OAR_ENABLE` | `0` | Master gate. When 1: SessionEnd queues pending records (v0.5.1 already), labeler runs inline on next cycle when due. |
| `PP_OAR_REF_TAU` | `0.5` | Token-bigram Jaccard threshold for `referenced`. Calibrate on a labeled sample before changing. |
| `PP_OAR_LABEL_PER_CYCLE_CAP` | `5` | Maximum pending rows the inline labeler processes per cycle. Manual catchup via `polymath oar-label --all-due` bypasses. |
| `PP_OAR_LABEL_MAX_ATTEMPTS` | `3` | Attempts before a pending row moves to `oar-stuck.jsonl`. |
| `PP_OAR_ROW_TIMEOUT_S` | `3` | Per-row soft cap on labeling work. Timeout → increment attempts, leave in pending. |
| `PP_HALLUC_GATE_ENABLE` | `0` | Enables `pp_halluc_verify_citations` post-check in SHADOW mode — emits `halluc_post_would_drop` telemetry but does NOT flip verdicts (preserves OAR denominator). |
| `PP_HALLUC_GATE_ACTIVE` | `0` | When 1, post-check failures actually flip critique PASS → DROP. Requires `PP_HALLUC_GATE_ENABLE=1`. Default off; do not enable while collecting OAR baseline. |
| `PP_HALLUC_GATE_DEEP` | `0` | Adds ctags fallback for symbol resolution. Only enable if ctags is in PATH. |

`PP_HALLUC_GATE_HARD` (active-mode + skip retry entirely) is **deliberately not in v0.5.2** — deferred to v0.5.3 after FPR data is collected. v0.5.2's `_ACTIVE` flag is the intermediate step: post-check can flip a verdict, but the drop still flows through the retry-router (LOW confidence → cheaper retry).

### F. State files

| File | Owner | Schema | Rotation |
|---|---|---|---|
| `oar-pending.jsonl` | SessionEnd hook + labeler | `{sid, lens, hash, inject_ts, scan_at_epoch, attempts, status}` | **No size-based rotation.** Rows are removed only when labeled or quarantined → file grows bounded by pending workload, not log size. (Avoids the silent-rotation-loss bug GPT review caught.) |
| `oar-labeled.jsonl` | `pp_oar_label_pending` | `{sid, lens, hash, inject_ts, labeled_at, outcome, evidence_id, confidence, evidence:{...}}` | Standard `_pp_rotate_jsonl` at 10MB. Old labeled data is queryable via `.1`. |
| `oar-stuck.jsonl` | `pp_oar_label_pending` (on 3rd failed attempt) | `{sid, lens, hash, inject_ts, attempts, last_error}` | Surfaced in doctor #20. Manual triage. |
| `transcript-tail-${sid}.txt` | inject-monitor-insight.sh (v0.4 already writes; v0.5.2 extends retention to scan-window max = 7d) | Last ~5KB of filtered user-turns | Per-session; cleaned by `polymath cleanup`. |

All files mode 0600 in 0700 dir.

### G. Invariants

1. **Off-by-default → byte-identity.** With `PP_OAR_ENABLE=0` AND `PP_HALLUC_GATE_ENABLE=0`, `bin/statusline.sh` STDOUT is sha256-identical to v0.5.1.0 baseline.
2. **Hot path budget.** Inline labeler runs in a `& wait`-bounded subshell with a 1s hard cap and `PP_OAR_LABEL_PER_CYCLE_CAP=5` row ceiling. Telemetry never blocks the cycle.
3. **Containment everywhere.** `pp_contain_path` is called BEFORE any cited path is passed to git, grep, ls, find, or any other tool. Section B's `git log -- <paths>` is no exception.
4. **No new LLM calls in v0.5.2.** Hierarchical eval gate (LLM second-stage on hallucination borderline) is deferred to v0.5.3.
5. **Pending must not rotate-lose unlabeled rows.** Pending file has NO size-based rotation. Rows leave pending only via labeled-or-stuck transition.

## Known limits (not bugs, calibration concerns)

These are flagged by GPT review as "uncalibrated" but are exactly what v0.5.2 itself produces data to address. Documenting so we don't pretend otherwise:

- `PP_OAR_REF_TAU=0.5` is a starting guess. Calibrate against a labeled sample after 1-2 weeks.
- `±20`-line proximity window for `acted` is a starting guess. Tune against post-merge data.
- Stopword min-token-length=4 mitigates short-symbol false positives but doesn't eliminate them.
- `transcript-tail-${sid}.txt` 5KB cap biases `referenced` toward false negatives in long sessions. Evidence line numbers shift if the tail is later rotated — `evidence_id` is "best-effort, point-in-time."
- Per-row timeout 3s × cycle cap 5 = up to 15s of git work per cycle. Acceptable inside the 5-min interval but bears monitoring.
- **Cycle-wide vs per-observation citation allowlist** (caught during plan-writing): the hallucination post-check (§C) reuses `pp_extract_citations` from `lib/citations.sh`, which produces a single allowlist for the WHOLE grounded blob per cycle, not a per-observation allowlist. This means observation A citing symbol X (legitimate for A's lens) is the same allowlist as observation B citing X (potentially illegitimate for B). The post-check still catches OFF-allowlist citations (e.g., fabricated function names), so it's a correctness-preserving simplification, not a bug — but the per-observation-context check is genuinely v0.5.3 territory.
- **15s watchdog uses `kill -0` poll, not `wait -t`** (bash 3.2 portability). Hard kill on overrun mitigated by atomic-rename inside `pp_oar_label_pending`, but worth a self-test on a real mono-repo before flipping `PP_OAR_ENABLE=1` in production.

## Silent dependencies (explicit so they're tested)

- `git` ≥ 2.20 (rename detection thresholds, `--diff-filter`).
- `ctags` in PATH only required when `PP_HALLUC_GATE_DEEP=1`.
- `transcript-tail-${sid}.txt` format owned by `hooks/inject-monitor-insight.sh` (v0.4); v0.5.2 extends its retention but reads the same format. Doctor check #20 also validates the tail file exists when OAR is enabled.
