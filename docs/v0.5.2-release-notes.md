# Pair Polymath v0.5.2 → v0.5.2.1 release notes

*Two releases shipped in 48 hours. Both went through 3 rounds of GPT-5 coworker spec review + multi-reviewer-per-task implementation. Combined, the cadence caught 17 silent-correctness bugs pre-merge that I want to call out, because the catch rate is the point.*

---

## TL;DR

- **v0.5.2** (PR #77) — OAR (Observation→Action Rate) measurement plumbing + shadow-by-default hallucination verifier. Adds the substrate to ask: "did the user actually act on this lens observation, or just ignore it?" Plus a verifier that flags PASS observations citing non-existent code.
- **v0.5.2.1** (PR #78 + #79) — Planner / grounding fix. The earlier framing was "sharpen the personas." Real data showed 63-81% of lens DROPs were a grounding/validator-mismatch artifact, not persona quality. v0.5.2.1 fixes the plumbing instead. Persona work deferred to v0.5.3.

All four kill-switches default off. STDOUT byte-identical to v0.5.1.0 until you opt in. 862/862 bats green; cross-platform CI verified (macOS + Ubuntu).

## Longer-form blog draft

### The interesting bug pattern: "you're blaming personas"

For two months, I'd been planning v0.5.1.1 as "sharpen the personas." The 7 specialist lenses in Pair Polymath each have a `system_prompt_addition` in their JSON config — a persona like "you are a staff engineer who has done thousands of code reviews and has a nose for the bug nobody else has spotted." The plan: tighten the prompts that under-perform.

Then I shipped v0.5.2 (OAR + hallucination gate) and finally had data. 26 cycles in one session. 7 lenses each. DROP rates by lens:

| Lens | DROP % |
|---|---:|
| UX_DESIGN | 81% |
| PRODUCT_BIZ | 81% |
| ENGINEERING | 72% |
| PERF_FINOPS | 72% |
| STRATEGIC_FOUNDER | 72% |
| SECURITY | 63% |
| COGNITIVE_FLOW | 63% |

Across the board, between 63% and 81%. My persona hypothesis would have predicted UX_DESIGN and PRODUCT_BIZ being outliers (those were the lenses I'd noticed reaching for editorial commentary). The data said: yes those are highest, but ALL of them are bad. Persona quality can't be the whole story.

I dropped the spec into GPT-5 with a "review like a coworker" prompt. Reply:

> "You're blaming personas, but the drops are a plumbing artifact: you fan out lenses with no eligible surfaces and the evaluator rejects both missing citations and non-observations — so you're measuring grounding/validator mismatch, not persona quality."

Three concrete causes once I looked:

1. **Symbol-inventory drift.** Lens prompts saw symbols from `grep` across cwd. The critique validator's allowlist saw symbols from FILE-READ of the planner-picked file. The two sets diverged. Lens cited a grep-only symbol → critique DROPped with "not in allowlist."
2. **No SILENT contract.** Lenses had a SILENT sentinel they could output ("nothing in my domain here"), but the cycle scored it as DROP — punishing legitimate non-observations.
3. **No eligibility gate.** UX_DESIGN got fanned out in cycles with nothing UI-touchable to observe. Personas dutifully reached for Jakob's law or "the personas in the lens JSON are buried" (correctly DROPped as meta-commentary).

v0.5.2.1 fixes those three things. Persona work moves to v0.5.3 — by which time real shadow data will tell me if persona tightening is still needed at all.

### The discipline that catches the bugs

For each plan-task: spec compliance reviewer + code quality reviewer + GPT-5 review, in parallel. Apply real findings inline. Commit. Next task.

Cost: ~3× the LLM calls per task. Benefit: 17 silent-correctness bugs caught across two releases before any reached `main`. Highlights, by reviewer:

**GPT-5 caught** (subtle correctness, no project context):
- `||` inside `$(...)` never fires because the pipeline's exit is the last command's
- `|` separator collision in row identity hash → switched to ASCII 0x1F US separator
- `LC_ALL=C` inconsistent in numerator vs denominator greps (locale mismatch silently broke percentages)
- `group_by(.lens)` without `sort_by(.lens)` first (split non-contiguous groups)
- Doctor #21 jq-missing/JSONL-malformed silently returns green, defeating the silent-failure sentinel itself

**Spec compliance reviewer caught** (plan drift, naming):
- Function naming + signature drift
- Wiring-slot placement in the doctor checks list
- `--outcome` filter eating the per-lens denominator

**Code quality reviewer caught** (portability, races):
- Bash 3.2 portability violations
- mkdir-lock vs raw mv races on shared state
- Trap RETURN leak across two consecutive tasks (same bug pattern, only caught because reviews were independent)

**CI (Ubuntu) caught:**
- `timeout(1)` execvp can't resolve shell functions → every OAR detector returned 127 on Ubuntu, 0 on macOS
- GNU `realpath` returns 0 for non-existent paths → hallucination gate gave free PASS to hallucinated cites on Ubuntu

Two memory entries are now in my project memory for future sessions: *"realpath portability trap"* and *"timeout(1) and shell functions trap."* Worth memorializing so the next portable-bash project doesn't re-discover them.

### What ships in v0.5.2.1, concretely

- **SILENT first-class** — recognized pre-critique, distinct outcome from DROP/IGNORED, with closed-enum `silent_reasons` per lens (e.g., UX_DESIGN can SILENT with reason `no_ui_surface` but not `no_strategic_angle`)
- **Symbol-inventory unified** — both lens prompts and critique allowlist now read FILE-READ-derived symbols only. Grep hits go into a separate `NEARBY MENTIONS (NOT CITABLE)` block. Drift hash invariant + doctor #22 alarm catch any future regression.
- **Planner eligibility gates** — each lens JSON declares globs that define what surfaces it can observe. UX_DESIGN's globs cover `**/*.tsx`, `**/components/**`, `**/styles/**`, etc. STRATEGIC_FOUNDER + COGNITIVE_FLOW use `kind: always` (they observe meta-state, not files). Router prunes ineligible lenses from the pick before quota.
- **4 independent kill-switches:** `PP_LENS_GATES_TELEMETRY`, `PP_INVENTORY_UNIFY_ACTIVE`, `PP_SILENT_V2_ACTIVE`, `PP_LENS_GATES_ACTIVE` — each revertable independently via `polymath lens-gates {status,enable,disable}`.
- **Dual-write schema migration** — v0.5.2.1 writers emit both v1 and v2 fields concurrently for 30 days, so v0.5.2.0 readers continue parsing the artifacts without crashing.

### What's next

v0.5.3 (DIM — Developer Insights Module) is the next major release, but it's gated on real shadow data from v0.5.2's OAR measurement substrate. I've enabled `PP_OAR_ENABLE=1` + `PP_LENS_GATES_TELEMETRY=1` on my own machine to start accumulating signal. In 1-2 weeks I should know whether the inventory unification + SILENT fix alone moved drop rates enough (in which case eligibility gating in Stage D might be optional), or whether the full Stage D activation is needed.

If the data justifies it, v0.5.1.2 ships the offline replay harness GPT-5 suggested as the cleanest A/B variant infra — randomize at lens-invocation, not session. Until then: shadow + measure.
