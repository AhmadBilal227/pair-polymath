The most recent reference plan in this repo is `docs/superpowers/plans/2026-05-17-v0.5.1.1-planner-grounding-fix.md` — mirror its task shape (`### Task N: Name`, `**Files:**` block, `- [ ]` checkbox steps each with code + commands + expected output, commit step at the end of each task).

Plan structure (mandatory):

- 6-8 tasks, ordered so an in-flight partial implementation never makes the cycle worse than today
- Each task self-contained: failing test → minimal impl → passing test → shellcheck → suite no-regression → commit
- Self-review checklist at end (per writing-plans skill)
- Done criteria

## Anti-patterns to avoid

- Do NOT write a plan that has "TBD", "TODO", "similar to Task N", or "fill in details". The writing-plans skill explicitly bans these. Every step must contain the actual code/command/expected-output.
- Do NOT propose code that's not in the spec (e.g., a `polymath pause` subcommand, a `PP_PAUSE_VISIBLE` flag, a colored status label upgrade). Those are out of scope per the spec's "non-goals" section.
- Do NOT skip the bats-runs-and-fails step before each implementation step. TDD discipline: RED before GREEN.

## Iteration discipline (per ralph-loop pass)

Each iteration:
1. Re-read `docs/v0.5.4-pause-ux-spec.md` (spec is the source of truth)
2. Re-read the current state of `docs/superpowers/plans/2026-05-18-v0.5.4-pause-ux.md` (if exists from prior iteration)
3. Identify the next gap: missing task? incomplete code block? non-measurable step? wrong line range?
4. Edit/write the plan to close that gap
5. Self-critique:
   - Does every task have a failing-test step BEFORE the implementation step?
   - Does every code block contain real code (no placeholders)?
   - Does every command have an "Expected output" line?
   - Does every task end with a `git commit` step with a real commit message?
   - Does the cumulative task list cover all 4 spec Changes + all 6 ACs?
6. If plan is complete and consistent, append `<promise>PLAN-COMPLETE</promise>` and stop
