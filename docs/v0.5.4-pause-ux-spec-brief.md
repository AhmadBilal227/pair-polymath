# v0.5.4 Pause UX — Spec brief for ralph-loop iteration

## Goal

When the user runs `polymath disable` (sets `PP_EXTERNAL_LLM=0`), the statusline should VISIBLY show paused state instead of rotating stale cached observations. Also: the prompt-injection hook should not inject stale cached observations into Claude's context when paused.

Today's behavior: `polymath disable` blocks the next LLM cycle from STARTING, but the statusline keeps rendering whatever's in the lens cache. From a UX standpoint the system looks alive even after "disable." Plus `hooks/inject-monitor-insight.sh` still injects cached observations into Claude's prompt context, making "pause" non-inert for the actual user-facing surface (Claude's behavior).

## Findings from exploration (pass-1)

Three Explore agents already mapped the relevant code. Use these as ground truth:

### Code geography

- `bin/statusline.sh:770-773` — PP_EXTERNAL_LLM gate that blocks the parallel cycle from starting new LLM calls. Today this is the ONLY check.
- `bin/statusline.sh:2611-2661` — cache-read loop that probes `cc-monitor-$SESSION-$LENS.txt` files. Currently runs regardless of PP_EXTERNAL_LLM. **Should short-circuit when paused.**
- `bin/statusline.sh:2663-2767` — line-2 rendering. Three fallback branches at 2746-2766 (budget-red, budget-warn, generic idle). **Need a fourth: paused.**
- `hooks/inject-monitor-insight.sh:42-58` — reads cache observations and injects them into Claude's context. **Should short-circuit when paused.**
- `bin/polymath:1129-1130` — `polymath disable` writes `PP_EXTERNAL_LLM=0` to user.env. Does NOT clear cache today. **Should truncate cache atomically.**
- `bin/polymath:1134-1135` — `polymath enable` writes `PP_EXTERNAL_LLM=1`. **Leave cache empty; first cycle backfills.**
- `bin/polymath cache clear all` at `bin/polymath:303-308` already exists — disable should reuse its truncation path, not duplicate logic.

### Existing UX voice (must match)

Statusline already has the paused-glyph precedent at `bin/statusline.sh:2760`:

```
◌  paused — daily budget near cap (X% headroom); resets at local midnight
```

Use `◌` (U+25CC, dotted circle) + dim color + explicit reason + recovery hint. Parallel copy for the LLM-disabled case:

```
◌  paused — LLM cycle disabled (polymath enable to resume)
```

Other voice patterns observed:
- "(polymath enable to resume)" matches the project's recovery-hint pattern (see `docs/troubleshooting.md`: "polymath enable to re-enable")
- DIM_A escape color for paused state (already defined in statusline at lines 273-312)
- `polymath status` already prints `External LLM: 0` (or 1) — keep that. Maybe upgrade to a colored `paused` / `active` label.

### OAR / byte-identity / hidden interactions

- `test/v0.5.1-byte-identity.bats` (3 tests) pins that with all v0.5.x flags off, statusline STDOUT is byte-identical to v0.5.0 baseline. PP_EXTERNAL_LLM default is 1, so the new paused branch only fires when user opts in via disable — byte-identity should hold. **Verify in the spec; add a test if uncertain.**
- OAR labeler (`lib/oar.sh`): when paused, no new cycles → no new pending rows → no labeler activity. No outcome=paused needed.
- `hooks/session-end.sh:141-158` reads cache for OAR pending row population. When paused with a cleared cache, this becomes a no-op. **Check the spec covers this edge — should be benign.**
