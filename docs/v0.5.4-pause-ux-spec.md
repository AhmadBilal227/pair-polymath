# v0.5.4 — Pause UX: visible paused state across all three read paths

**Status:** spec round 1 (ralph-loop iteration 1)
**Author:** AhmadBilal227 + pass-1 Explore swarm findings
**Date:** 2026-05-18
**Class:** bugfix (not feature) — closes UX gap in `polymath disable` ↔ statusline interaction

---

## Goal

When the user runs `polymath disable` (sets `PP_EXTERNAL_LLM=0`), the system should be VISIBLY paused — not silently masquerading as alive. Three concrete user-visible surfaces are wrong today:

1. **Statusline line 2** keeps rotating cached lens observations from before the disable, indistinguishable from a healthy active state.
2. **Prompt-injection hook** (`UserPromptSubmit`) keeps injecting cached observations into Claude's context as `[BACKGROUND ADVISORY]`, so Claude still SEES the pre-disable advisor output on every prompt — "pause" is not inert for the actual load-bearing surface (Claude's behavior).
3. **`polymath disable` does not clear the cache atomically**, so even after the next cycle is blocked, the stale cache persists.

The reframe: pause means INERT, not just "no new cycles start." Inert = nothing on disk influences user-visible output. Three read paths, one disable.

---

## Reframe / non-goals

- **NOT a behavior change.** This is a bugfix: today's behavior is incoherent ("disabled but still showing"). Default OFF state when user has never touched `polymath disable` is unchanged. No new kill-switch.
- **NOT a full uninstall path.** `bin/uninstall.sh` already exists for full removal. Pause is an opt-in soft state.
- **NOT a separate `polymath pause` subcommand.** Reuse `polymath disable` semantic; this spec aligns the existing surface, doesn't add a new one.
- **NOT a new OAR `outcome=paused` enum value.** Paused means zero cycles run → zero pending rows → labeler is naturally a no-op. The existing `dispatched_count=0` covers this correctly.
- **NOT a redesign of `polymath status` or `polymath doctor` output formats.** Surgical additions only (one line + colored label).

## Four concrete changes

### Change 1 — Statusline line 2 shows paused glyph when PP_EXTERNAL_LLM=0

**Today** (`bin/statusline.sh:2746-2767`): the idle-fallback block has 3 branches (budget-red / budget-warn / generic-idle). None check `PP_EXTERNAL_LLM`. When paused, statusline either:
- Rotates whatever's in the cache (looks alive) — see Change 2 for why this happens.
- Or falls through to "no fresh insight in last Xm" — looks idle, not paused.

**Fix:** add a 4th branch at the **HEAD** of the if/elif chain. Highest priority (paused supersedes budget messages since user explicitly opted out):

```bash
# bin/statusline.sh:2746 — new first branch
if [ "${PP_EXTERNAL_LLM:-1}" = "0" ]; then
  topic_line="${aurora_hue:-}◌${R}  ${DIM_A}paused — LLM cycle disabled (polymath enable to resume)${R}"
elif [ "$_idle_pct" -le "$(( 100 - _idle_red ))" ]; then
  # ... existing budget-red branch
```

**Voice match:** the glyph (`◌`), color (`DIM_A` dim), and recovery-hint copy pattern (`(polymath enable to resume)`) all match `bin/statusline.sh:2760` and `docs/troubleshooting.md` precedent.

**LOC:** +3 lines of bash.

### Change 2 — Statusline cache-read loop short-circuits when paused

**Today** (`bin/statusline.sh:2611-2661`): the loop probes `cc-monitor-$SESSION-$LENS.txt` files and populates `mon_topic`/`mon_body` regardless of `PP_EXTERNAL_LLM`. Even if Change 1's paused branch is present, the cache-read loop will populate `mon_topic` first — and the line-2 rendering logic at 2730-2745 selects `mon_topic` over the fallback when `mon_valid=1`.

So Change 1 alone is not enough — the paused branch will never fire if the cache happens to have a valid recent observation.

**Fix:** add an early short-circuit at the head of the cache-read loop. When paused, leave `mon_topic` empty so the fallback chain (now starting with the paused branch from Change 1) fires.

```bash
# bin/statusline.sh:2611 — new gate ABOVE the cache-read loop
if [ "${PP_EXTERNAL_LLM:-1}" = "0" ]; then
  mon_valid=0
  # mon_topic / mon_body intentionally left empty;
  # idle-fallback chain (see :2746+) renders the paused message.
else
  # ... existing cache-read loop at 2611-2661
fi
```

**LOC:** +4 lines of bash + structural indentation of the existing loop body (cosmetic — no logic change).

---

### Change 3 — `hooks/inject-monitor-insight.sh` skips injection when paused

**Today** (`hooks/inject-monitor-insight.sh:42-58`): reads `cc-monitor-$SESSION-$LENS.txt` for every active lens and emits a `[BACKGROUND ADVISORY — UNTRUSTED]` block on stdout. Claude Code captures that stdout and injects it into Claude's prompt context on every `UserPromptSubmit`. **This is the actual user-impact surface — Claude's behavior — and it continues to be influenced by stale cached observations after pause.**

**Fix:** add an early-exit at the top of the script body, before the lens-iteration loop. Honor `PP_EXTERNAL_LLM=0` consistently with statusline.

```bash
# hooks/inject-monitor-insight.sh — near the top, after env loading
if [ "${PP_EXTERNAL_LLM:-1}" = "0" ]; then
  # Paused: emit nothing on stdout (no advisory injection).
  # `polymath enable` reactivates injection on the next prompt.
  exit 0
fi
```

**LOC:** +5 lines of bash (early-exit + comment).

**Test impact:** existing tests for this hook do not exercise PP_EXTERNAL_LLM=0; need a new bats test to pin behavior.

---

### Change 4 — `polymath disable` clears the cache atomically

**Today** (`bin/polymath:1129-1131`): writes `PP_EXTERNAL_LLM=0` to `user.env` and prints the confirmation. Does NOT touch cache files. So even after Changes 1+2+3, if the user runs `disable` while a fresh cycle's observations are on disk, the cache still has them — Changes 1+2 make line 2 say `paused`, Change 3 stops injection, but `polymath status` and `polymath history` would still see the orphan observations.

**Fix:** call the existing cache-clear path inline. `bin/polymath:303-308` already has `polymath cache clear all` which truncates `cc-monitor-*` + `cc-tips*` + idempotency files atomically with budget files preserved. Disable should reuse this same code path — not duplicate the logic.

```bash
# bin/polymath:1129-1131 — extended
disable)
  _pp_set_user_env_var PP_EXTERNAL_LLM 0 || exit 1
  # Truncate observation + tip caches so paused state is INERT immediately
  # (not just for new cycles). `polymath cache clear all` preserves budget
  # files and writes mode 0600. See bin/polymath:303-308 for the canonical
  # truncation path.
  _pp_cache_clear_all >/dev/null 2>&1 || true
  printf 'LLM cycle disabled and observation cache cleared. Status-only mode active.\n'
  ;;
```

**Note:** the existing `cache clear all` command body should be refactored into a `_pp_cache_clear_all` helper so both the `cache clear all` subcommand AND `disable` invoke the same code. Refactor lives at `bin/polymath:303-308`.

**LOC:** ~10 lines of bash (refactor existing 6-line cache-clear into a helper + call from both sites).

**`polymath enable` does NOT clear cache** — there's nothing to clear (Change 4 already truncated it on disable). The first cycle within 5 min refills the cache; the existing `idle — no fresh insight in last Xm` branch covers the gap.

## Acceptance criteria

All measurable via bats:

1. **AC1 — Statusline shows paused glyph.** With `PP_EXTERNAL_LLM=0` set, running `bash bin/statusline.sh` against the standard test fixture (`test/fixtures/stdin-sample.json`) emits a line containing the substring `paused — LLM cycle disabled`. Fails today.
2. **AC2 — Statusline ignores cache when paused.** With `PP_EXTERNAL_LLM=0` AND a pre-existing `cc-monitor-$SESSION-$LENS.txt` file containing a valid observation, statusline still emits the paused glyph (not the cached observation). Fails today.
3. **AC3 — Inject hook stays silent when paused.** With `PP_EXTERNAL_LLM=0` AND a pre-existing valid cache, `bash hooks/inject-monitor-insight.sh < /dev/null` emits ZERO bytes to stdout. Fails today (today it emits the advisory block).
4. **AC4 — Disable clears cache.** Running `bash bin/polymath disable` after a cycle has populated `cc-monitor-*` files results in those files being removed (verified by `[ ! -e ... ]`). Fails today.
5. **AC5 — Byte-identity preserved when default-enabled.** With `PP_EXTERNAL_LLM` unset (or `=1`), statusline STDOUT remains byte-identical to v0.5.3 baseline. The existing `test/v0.5.1-byte-identity.bats` (3 tests) must continue to pass without modification — the new paused branch only fires when user opts in.
6. **AC6 — Enable restores normal flow.** After `polymath disable` followed by `polymath enable`, the next cycle (≤5 min) populates the cache, and statusline transitions from `paused` → `idle — no fresh insight in last Xm` → fresh lens observation. (Manual / runtime; not auto-testable in bats.)

## Risk + edge cases

- **Race: disable fires while a cycle is mid-flight.** The mid-flight cycle finishes and writes its cache (Change 4 truncates it on disable, but the cycle may write AFTER the truncation). Mitigation: the cycle's gate at `bin/statusline.sh:772` rechecks `PP_EXTERNAL_LLM` — but only at cycle START, not before each write. Worst case: one stale cache file appears after disable, gets rotated on next refresh (≤30s for next refresh + Change 2's short-circuit ignores it anyway). **Accept as benign.**
- **Race: enable fires while paused-message is displaying.** Statusline reads `PP_EXTERNAL_LLM` on every refresh (≤30s); transitions naturally on next refresh. **Accept.**
- **`session-end.sh:141-158` reads cache for OAR pending row population.** When paused with a cleared cache, this becomes a no-op (no cache → no pending row written). Benign: matches the "no cycles ran, no labeler activity" model. **No code change needed.**
- **`dismiss.sh:500` scans `cc-monitor-injected-hash-*` for dismiss-rule counting.** Cleared on disable as part of cache clear all. Effect: dismiss-counter resets when user disables. **Accept** — disable is a deliberate state reset; a separate `polymath dismiss list` shows the rules themselves, which are NOT in the cache.
- **Cosmetic: `polymath status` shows `External LLM: 0` today.** Could upgrade to colored `External LLM: 0 ◌ paused` label for consistency with statusline. **Defer to follow-up — not blocking this spec.**

## Open questions

- **(Q1) Should `polymath disable` ALSO clear the `cc-monitor-injected-hash-*` idempotency files?** Pro: clean slate, no residual injection-state. Con: if user re-enables within 30 min, the existing dedup window resets, which could spam Claude. Recommendation: clear them (current Change 4 plan via `cache clear all`). Dedup re-establishes on first post-enable cycle.
- **(Q2) Should `polymath disable` ALSO clear `oar-pending.jsonl`?** No — pending rows represent observations that ALREADY fired in Claude's context (pre-disable). They should still get labeled when the next cycle runs (post-enable). The labeler is gated on `PP_OAR_ENABLE`, not `PP_EXTERNAL_LLM`. **Decision: leave pending file untouched.**
- **(Q3) Should `hooks/session-end.sh` also short-circuit on `PP_EXTERNAL_LLM=0`?** No — SessionEnd's job is to record what happened in the session, including the fact that the LLM cycle was off. **Decision: leave SessionEnd untouched.**
- **(Q4) Copy choice: `paused — LLM cycle disabled (polymath enable to resume)` vs `paused — disabled (polymath enable)` vs `polymath off`?** The first is most precise and matches `bin/statusline.sh:2760`'s existing voice ("paused — daily budget near cap"). Locked.
